# Agent Platform 产品需求文档

- 文档版本：0.3
- 日期：2026-09-16
- 状态：首期产品语义已确认，进入架构设计与迭代规划阶段
- 主项目：通用 Agent 服务平台
- 业务产品：根目录 `samples/` 下的包／实例标准模板、语义交互包与文本查重实例

## 1. 背景与首期目标

业务系统拥有现成 API，但新建 Agent 时仍需重复处理模型接入、工具调用、参数校验和执行状态。平台将模型交互能力作为业务包挂载，由实例组织完整业务入口与流程，组合一个或多个业务包及一个或多个配置形成可调用服务。首期以桌面程序运行。

**首期至少交付两个产品：服务平台产品和业务示例产品。主要目标是验证平台闭环及平台与包的方向，业务示例验证可用性与严格的输入输出契约，不验证 LLM 判断的准确性。**

### 1.1 必须交付

| 产品 | 首期内容 | 验收重点 |
| --- | --- | --- |
| 服务平台 | 服务配置页、环境配置页、包加载、Python 通用流程块注册与调用、实例版本与历史回退、任务调用和结果查询 | 从挂载、配置保存到调用、结果校验的完整闭环 |
| 业务产品 | 包与实例标准模板、平台接入契约与样例、语义交互包及可执行的文本查重实例 | 能接入平台，输入输出严格校验，同时产出定量与定性报告 |

标准模板需包含包清单、模型交互前后的输入输出与配置契约、包调用入口、平台能力调用方式，以及独立的实例入口与流程样例；具体组织方式在技术设计中确定。它不能只是一份目录规划。

首期查重规模为一篇约 1500 字文本与另外六篇约 1500 字文本比较。该规模是功能验收样例，不是已承诺的系统容量上限。性能优化后置。

### 1.2 首期不包含

- 权限控制与独立授权服务接入、生产级多租户治理。
- 数据库直连、数据库连接管理、本地数据库持久化、跨重启历史恢复。
- 完整 LMS 课程／作业数据采集、提交版本策略、分页一致性及学生身份关联。
- 教师复核工作流、复核结论存储、LMS 教师端页面改造。
- 复杂查重业务规则、模型准确率评估、自动给出最终抄袭判定。
- 性能优化、通用防御性框架、自动兜底、复杂重试与任务恢复机制。
- 全量 Apifox 治理、通用可视化画布、包市场、任意第三方代码沙箱。
- 多 Agent 协作、长期记忆、RAG、向量数据库、代码及扫描件查重。

严格输入输出校验、明确报错和已约定的任务终止行为仍是首期必要逻辑，不因上述收敛而省略。

## 2. 概念与责任边界

| 概念 | 定义 |
| --- | --- |
| 业务包／服务包 | 可复用的模型交互单元，封装 LLM 交互前后的输入输出、Prompt 与必要处理，声明版本、包调用入口、配置及依赖；不包含完整业务流程 |
| 能力契约 | 一项依赖的输入输出结构与错误约定 |
| 环境配置 | 平台管理的模型连接、API 地址、认证引用及运行参数 |
| 服务配置 | 实例使用的一份配置单元，包括包参数、能力绑定、环境引用及预算；一个实例可组合多份配置 |
| 服务实例 | 完整业务入口、脚本与流程，以及一个或多个固定版本业务包和一个或多个固定版本配置的组合，拥有独立实例标识 |
| 服务 | 拥有稳定调用入口，指向服务中心当前选定的实例版本 |
| 通用流程块／功能块 | 明确输入输出的确定性 Python 代码，用于固定格式处理、清洗、转换或验证 |
| 实例流程 | 组织业务包、通用能力及确定性业务计算的完整业务实现 |
| 运行任务 | 一次实例调用及其固定版本、输入、状态、结果与错误 |

### 2.1 平台与包

- 平台负责配置页、环境管理、包挂载、实例版本、通用块注册与调用、模型调用、契约校验、任务状态和缓存记录。
- 实例负责完整业务入口、流程编排、确定性业务计算及最终报告；包负责 LLM 交互前后的输入输出、Prompt 与必要处理。业务代码存放于示例产品中，平台核心不包含查重算法或课程业务分支。
- 固定消息格式的解包、清洗与验证由 Python 通用块完成；例如判断哪个字段代表成绩等依赖语义的识别，由模型完成，并校验模型输出结构。
- 通用块本身是硬编码的确定性 Python 实现，不承载模型自主判断。实例流程将通用块与业务包组合使用。
- 包通过平台接口获取工具、模型和进度能力；实例返回结果后由平台校验保存，不硬编码环境地址与真实凭据。
- 首期只加载受信任的本地包，不要求第三方代码沙箱。

### 2.2 权限的后续方向

权限验证视为独立服务能力，后续可实现为可复用的通用包或流程，并作为服务实例通用流程的一部分接入。首个验证版本不实现权限检查，也不以拒绝未授权调用为验收条件。模型/API 的连接认证配置与业务调用者的权限验证是不同能力，前者仍在首期范围内。

## 3. 用户与主要路径

- 包／实例开发者：依照标准模板定义包契约与模型交互，并编写实例入口、流程和样例。
- 平台配置者：配置环境，挂载包，选择能力绑定，保存服务配置，查看历史和回退。
- 业务调用方：提供文本输入，提交任务，查询状态与报告。
- 教师：阅读定量、定性报告，自行决定是否构成抄袭；首期不建设教师复核系统。

```text
环境配置页配置模型／API 连接
  → 挂载本地包和实例流程，读取契约
  → 服务配置页组合包与配置，选择环境与通用流程块、填写参数
  → 校验并保存，生成立即生效的实例
  → 通过稳定服务入口提交输入并取得运行标识
  → 执行实例流程中的 Python 功能块与业务包调用
  → 校验输出并返回报告，或返回具体错误
```

挂载不自动执行业务操作。无效配置不得作为可调用实例生效；“保存后立即生效”指通过校验后的成功保存，无需另行启用。

## 4. 首期平台需求

### P01. 包加载与标准接入

- 读取本地包清单、版本、契约、入口和依赖，检查必要信息及依赖是否齐备。
- 同一包可被多个实例复用；每个实例组合一个或多个业务包和一个或多个配置，并提供独立业务入口与流程。
- 缺少依赖、配置不完整或契约无效时给出具体原因，不生成可调用实例。
- 提供可复用标准模板与接入样例，后续业务包依协议接入，不要求修改平台核心。

### P02. 服务配置页与环境配置页

| 页面 | 最小功能 |
| --- | --- |
| 环境配置页 | 配置模型连接、模型标识、凭据引用、API 连接及调用超时等必要参数，供服务配置选择 |
| 服务配置页 | 挂载／选择包与实例流程，组合配置，依 Schema 填写参数与预算，绑定环境与通用块，校验保存，展示生成的实例标识和版本，查看历史及发起回退 |

- 包通过 Schema 声明配置类型、必填项、默认值和说明。
- 凭据由平台环境管理，不写入业务包或日志。
- 保存校验失败时返回具体字段或依赖问题；成功保存后新实例立即可调用，不设置额外发布步骤。
- 首期不要求通用画布或任意表达式映射编辑器；固定转换通过注册的通用块选择与配置。

### P03. 实例版本、稳定入口与回退

- 一个服务提供稳定入口，指向当前选定的实例版本；更新成功后入口原子切换到新实例。
- 旧实例退役后不能直接接受新调用；需要在服务中心选择历史版本并回退后，才能由稳定入口再次调用。
- 每次更新完整保留旧实例的入口脚本、流程、业务包实际内容及配置，不能只保留原始文件路径或版本号。保存不可变快照，避免源文件后续修改破坏回退。
- 历史快照当前只保留在内存，同次桌面程序运行期间可回退；退出后清空，后续数据库版本才实现跨重启保留。
- 回退重新选用指定历史实例，不重新编造其版本；使用当前环境，回退前重新验证环境是否满足该实例要求。
- 包变更视为大版本更新；服务配置变更视为小版本更新；包与配置同时变更视为破坏性整体更新。入口脚本与流程的版本归类由架构设计确定。
- 更新生成新实例标识，不原地修改旧实例。每次任务固定提交时的入口、流程、包、配置与实际环境设置，更新或回退不改变已经排队或运行的任务。
- 环境配置独立于实例版本。存在引用该环境的排队、运行或取消等待任务时，不允许更新环境；空闲时可更新，后续任务使用新环境，LLM 地址等环境变化不改变实例版本号。
- 具体版本编码由技术设计确定，需区分包更新、配置更新与整体更新。

### P04. API 接入与 Python 通用流程块

- 包声明能力契约，平台支持绑定 API 或已注册通用流程块组成的接入流程。
- 通用块以 Python 代码实现并明确输入输出，输入、输出均执行运行时校验；首期提供代码注册与调用能力。
- 首期必须包含固定 API 消息格式的处理能力。例如 LMS 响应：

```json
{
  "code": "10000",
  "msg": "成功",
  "subCode": null,
  "subMsg": null,
  "bizData": ""
}
```

- 对该格式由确定性通用块检查成功码、提取 `bizData` 并按目标契约校验；失败时保留 `code`、`msg`、`subCode`、`subMsg` 等可用错误信息，不转换为空的成功结果。
- 此示例不将 `bizData` 限定为字符串；其实际类型以绑定能力的契约为准。
- 例如“哪个字段是成绩列”等语义映射交给模型判断，模型返回的结构仍需校验；该例说明职责边界，不增加首期成绩识别业务包的交付要求。
- 通用块能力属于首期平台交付，即使查重实例直接接收文本，也应单独通过样例验证通用块的注册、绑定、执行和校验。

### P05. 严格契约与模型环境

- 用户输入、通用块输入输出、API 响应、LLM 输出、最终报告均执行相应运行时校验。
- 契约明确字段类型、必填项、范围、枚举、嵌套结构与未知字段处理方式。
- 从单一契约来源派生类型、校验规则与公开 Schema，避免手工维护多套规则。
- 校验失败指出阶段、字段路径和原因，不通过强制类型转换、静默填值或自动兜底制造合规结果。
- 包定义 Prompt、模型输出契约以及可配置的 loop 和 token 使用上限；平台管理连接、凭据、超时，统一执行任务预算并提供模型调用接口。
- 模型输出结构校验与模型语义判断准确性是两件事。前者必须验收，后者首期不验证。
- 不建设复杂自动重试、模型降级或自动修复输出机制；发生失败明确报错。

### P06. 任务状态、取消与关闭

- 提交后立即返回运行标识，支持查询状态与结果；执行不依赖提交请求的 HTTP 连接持续存在。
- 状态至少包含 `queued`、`running`、`completed`、`failed`、`cancelled`；取消等待期间需可识别，具体采用状态还是标记由实现确定。
- 首期在应用缓存中记录输入、实例及版本、状态、结果和具体错误，不实现任务恢复。

| 场景 | 首期行为 |
| --- | --- |
| 正常完成 | 实例最终输出通过契约校验后完成；查重实例要求定量与定性报告均成功 |
| 取消排队任务 | 不再开始执行；无在途 LLM 请求时可完成取消 |
| 取消运行任务 | 收到请求后不发起后续步骤；等待当前 LLM 请求返回且传输结束后，才确认取消成功，不再将本次任务标为完成 |
| 退出桌面程序 | 中止排队与运行任务，同时停止本地与 LLM 的请求／响应传输，不采用主动取消时的等待规则 |
| 应用重启 | 不恢复原任务；内存记录清空，原运行标识返回明确的记录不存在信息，不虚构旧任务状态 |
| 预算耗尽、超时、调用失败 | 返回对应的具体失败原因，不用单一通用报错，也不返回成功的空报告 |

停止本地传输不承诺远端模型供应商已停止计算或计费。取消等待期间出现超时或传输失败，优先报错，任务记为 `failed` 并保留取消请求记录；正常完成等待后记为 `cancelled`。

失败或取消后，任务保留终态和错误，实例恢复可接收任务的就绪状态，丢弃本次临时执行数据；不自动重试，不撤销已完成的外部 API 操作。退役实例仍受退役限制，不能因任务结束而重新开放调用。

错误至少包含类别、失败步骤与可读原因，按场景附带字段路径或上游错误信息；例如配置错误、输入校验失败、预算耗尽、模型请求超时、API 调用失败、模型输出校验失败。错误信息不暴露凭据。

### P07. 对外调用与去重键

以下是建议接口语义，路径不是已实现协议：

| 接口 | 语义 |
| --- | --- |
| `GET /services` | 列出稳定服务标识及其当前实例版本，首期不做权限过滤 |
| `GET /services/{serviceId}/schema` | 获取当前选定实例的输入输出契约、版本与样例 |
| `POST /runs` | 提交稳定服务标识与输入，固定当前选定实例，每次成功提交创建新任务并返回新的运行标识；首期不实现去重键 |
| `GET /runs/{runId}` | 查询状态、取消等待情况和具体失败原因 |
| `GET /runs/{runId}/result` | 获取实例最终结果；查重实例为定量及定性报告 |
| `POST /runs/{runId}/cancel` | 请求取消；请求已受理不代表已取消成功 |

**已确认：首期不实现去重键。** 每次通过校验并被接受的提交都创建新任务，不根据请求标识或输入内容复用已有任务。重复点击或请求重试可能产生重复任务及模型调用。去重机制不作为首期交付或验收要求；后续如需引入，再确定作用范围、有效期及冲突处理规则。

### P08. 运行记录与缓存

- 提供定位问题所需的阶段、通用块调用、模型调用与校验失败记录；首期不建设完整监控平台。
- 配置、历史实例、任务、报告等运行数据当前仅保留在应用内存缓存中。包源码及标准模板仍为项目文件。
- 缓存保留支持同一应用运行期间的历史查看与回退；重启清空，不承诺跨重启留档。
- 日志不输出真实凭据，不默认打印整批学生答案。
- 流程验证通过后，随数据库能力将相关记录持久化到本地，保留周期等规则届时确定。

### P09. 单任务预算

- 包提供可配置的 `loop` 上限与 token 使用上限，实例配置将一个或多个包的预算声明组合成可执行的任务预算。具体组合规则由架构设计确定。
- 一次完整业务包调用计一轮 loop；已开始但报错的调用也计一轮，重试是新的一轮。首期平台不自动重试。
- 每次任务／流程状态流转前检查预算；终止与清理不能被预算检查阻塞。
- token 按单任务累计输入与输出计量，上限是否严格执行作为配置。严格与非严格模式的计量、限额及无用量信息处理由架构设计明确，不将估算称为精确计量。
- 预算耗尽返回具体错误；显示 loop、token 使用量及 token 是否为估算。

## 5. 业务包协议与实例模板

包类似可复用依赖，一个实例可组合多个包与多个配置。包封装 LLM 交互前后的输入输出，不拥有完整业务入口与业务流程。

| 包声明 | 含义 |
| --- | --- |
| packageId / version | 包标识与版本 |
| name / description | 能力说明 |
| runtime / entry | 运行时要求与包调用入口 |
| inputSchema / outputSchema | 模型交互单元的严格输入输出契约 |
| configurationSchema | 包参数及可配置的 loop、token 上限 |
| requiredCapabilities | 模型、API、通用块等依赖与契约 |
| examples | 有效及无效样例 |

实例定义单独声明业务入口、完整流程、服务输入输出契约、固定包依赖、一个或多个配置及能力绑定。包契约与实例最终报告契约分别负责各自边界。

标准模板同时提供包模板和实例组合样例，说明如何经由平台运行上下文调用包、通用块、模型、记录进度及返回结果。具体签名由架构设计确定。

规划目录：

```text
samples/
├── template/
│   ├── packages/              # 模型交互包模板
│   └── instance/              # 入口、流程、配置与服务契约样例
└── assignment-similarity/
    ├── packages/              # 语义分析包
    ├── instance/              # 完整查重流程与定量计算
    └── examples/              # 合成文本与报告样例
```

目录为组织示意，当前尚未实现模板或业务产品。

## 6. 业务产品：最小文本查重

### 6.1 目标与输入边界

比较一份当前学生作答／文章纯文本与其余学生作答／对照文章纯文本数组，同时提供定量重复文本相似度报告与定性文本语义抄袭分析报告。

“给定文章与给定数据库”的首期边界按本次输入约定收敛为：调用方提供目标文章和从对照资料中取得的文本数组；查重实例不负责数据库连接、检索或完整 LMS 数据采集。

建议字段名（最终以实现契约为准）：

| 输入 | 类型 | 含义 |
| --- | --- | --- |
| targetText | string | 当前学生的纯文本作答或待比较文章 |
| comparisonTexts | string[] | 其他学生作答或指定资料库提供的纯文本集合 |

不要求课程、题目、学生 ID、提交版本、快照或分页信息。对照项可通过数组索引关联报告，首期无需扩展为完整学生数据模型。

### 6.2 最小执行流程

1. 实例严格校验目标文本与对照文本数组。
2. 以确定性代码比较目标文本与各对照文本，生成定量重复文本相似度结果。
3. 实例调用语义分析业务包，由包组织模型交互，生成定性报告。
4. 校验模型输出与最终报告结构，返回两类报告；失败时返回具体错误。

首期无需候选召回、向量检索、题型分组、提交去重策略或复杂部分覆盖规则。

### 6.3 输出边界

- 定量报告：提供目标文本与各对照文本的数值相似度，注明计分尺度及采用的方法；以重复段落文本计分；空输入、清洗、计分分母和最小报告字段授权由设计给出简单方案，见架构设计文档，不让运行时 LLM 自行编造数值或改变契约。
- 定性报告：提供模型对语义相似、可能改写或潜在抄袭关系的分析理由与建议，并能关联到对照文本。
- 两类报告采用明确结构，不能仅依靠一段不受约束的自由文本作为服务返回值。
- 定量相似度不是抄袭概率；LLM 只提供建议，是否认定为抄袭由教师综合两类报告自行决定。
- 首期不输出作为最终判定的 `true/false`，不保存教师复核结论。未来可能增加 AI 的布尔结论，作为后续需求变更处理。
- 严格校验输出类型、字段和数值范围，不将 LLM 语义判断准确性作为首期验收指标。

### 6.4 功能样例

- 正常样例：一篇约 1500 字文本，与另外六篇约 1500 字文本比较，能够返回两类报告。
- 契约样例：输入字段缺失、类型错误、数组元素错误，以及模型输出缺字段／类型不符时，都应被拦截并返回具体原因。
- 定量算法以简单、可复现的样例验证实际计算行为，不能以常量或占位数字代替报告。
- 使用合成或经授权脱敏的文本。首期不设召回率、误报率、模型准确率或性能优化指标。

## 7. 后续扩展

流程确认可用后，再扩展本地数据库持久化、业务数据库连接及资料读取能力。平台状态存储与包访问业务数据库属于不同能力。

权限验证作为独立服务／通用包，后续可加入实例通用流程。性能优化、防御性机制、兜底、任务恢复、复杂查重规则与更多输入类型按实际需求逐步增加，不提前纳入最小验证版本。

## 8. 首期里程碑与验收

**首期必须完成 M1 与 M2，两类产品均需交付；平台闭环是主要验收目标。**

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| M0 需求基线 | 需求、项目说明、协作约定 | 范围一致，已确认项与待决策项分开 |
| M1 平台产品 | 两个配置页、包接入、Python 通用块、实例版本、缓存、任务调用 | 配置保存即生成可调用实例，调用后返回符合契约的结果或具体错误 |
| M2 业务产品 | 包与实例标准模板、接入样例、语义包及最小查重实例 | 按模板接入平台，完成 1 对 6 文本比较并输出定量与定性报告 |
| 后续扩展 | 数据库、权限、性能与业务规则等 | 另行确认，不作为首期阻塞项 |

首期检查清单：

- 服务配置页和环境配置页均可操作；缺失必要配置或依赖时不能保存为有效实例。
- 配置更新产生新版本和新实例，稳定入口立即切换；旧实例不能直接调用，同次运行期间可选择完整历史快照回退。
- 配置更新不改变已提交任务的实际包版本、配置和模型设置；关联环境有未结束任务时不能修改，空闲环境更新不改变实例版本。
- 一个实例能组合多个包与多个配置；包不承担完整实例流程。
- loop 按包调用尝试计数，失败尝试也计数；每次状态流转前检查预算，token 严格模式可配置。
- Python 通用块可注册、绑定和执行，固定 LMS 消息解包的成功与失败样例符合契约。
- 输入、通用块输出、模型输出及最终报告的结构错误被拦截，公开契约与运行时校验一致。
- 正常文本样例能得到真实计算的定量报告与模型生成的定性报告，不验收模型分析准确性。
- 取消请求受理与取消完成可区分；应用关闭停止本地模型传输，重启不恢复任务。
- 预算耗尽、超时和调用失败有不同、具体的报错，不以空报告伪装成功。
- 不依赖权限服务、数据库、向量服务或真实 LMS 页面即可完成首期闭环。
