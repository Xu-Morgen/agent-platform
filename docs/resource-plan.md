# 三类资源专项优化计划

基线：2026-09-17 用户确认的 V1。下列事项均为待实现；当前指导样例见 [资源手册](resource-guide.md)。保留 block、package、contract 三类资源，暂不引入新插件协议或资源市场。

## 通用块

现状：一个 Python 文件、一个入口，严格输入输出、依赖检查、内容快照；支持清洗、转换、判断和计分。当前参数只能作为输入接线，不能按业务包表单配置，也不需要模型预算。

| ID / 优先级 | 改进及边界 | 交付物 | 完成标准 |
| --- | --- | --- | --- |
| B1 / P1 | 块卡片展示用途、字段说明、支持的输入形态；区分转换块和判断块 | 目录卡片与输入输出帮助 | 无需打开源码即可找到字段转换和严格 bool 条件块 |
| B2 / P1 | 增加一次执行预览；优先复用纯块临时服务/任务语义，明确会执行代码 | 输入表单、输出/错误预览及临时资源清理 | 成功显示输出；错误定位字段；不切换用户已有服务版本 |
| B3 / P2 | 加载错误细化、依赖兼容提示、重新加载时明确版本冲突 | 可操作的修复指引 | 缺依赖、重复入口、类型错误和相同版本内容变化均有具体解释 |
| B4 / P2 | 明确耗时块的执行边界；测量后再引入受控进程执行 | 超时/取消协议及运行记录 | CPU 密集块不长期阻塞 API；退出不会遗留任务，不能简单用线程宣称可强制取消 |

样例基线：`samples/blocks/minimal.py` 展示最小入口出口，`complete.py` 展示嵌套输入、枚举、默认值和统计输出；README 说明 bool 条件及错误处理方式。块能力保持确定性；需要模型的处理通过业务包表达。

## 业务包

现状：清单、Prompt、参数模型、能力声明和内存内容快照；同包多个节点独立配置，模型/API/块能力由平台绑定。

| ID / 优先级 | 改进及边界 | 交付物 | 完成标准 |
| --- | --- | --- | --- |
| P1 / P1 | 参数表单覆盖嵌套对象、枚举、描述、默认值与必填；配置预检反馈靠近字段 | Schema 表单与错误定位 | 同包两个节点独立编辑，保存/重开后值一致，不误覆盖另一节点 |
| P2 / P1 | 保存前说明节点能力、模型协议、严格预算支持情况和全局/局部限制 | 能力摘要、预算解释 | 用户能理解为什么严格模式不可用；不静默降级；循环预算累计方式清楚 |
| P3 / P2 | 展示包更新影响与实例配置差异，提示受影响节点 | 版本差异预览 | 新包只影响新保存实例；在途任务及历史快照继续使用原代码和资源 |
| P4 / P2 | 完善开发模板说明、输出契约提示和资源一致性生成 | 包开发模板和契约同步指引 | 复制包、改标识、加载、配置后可完成一次真实交互，失败无伪造结果 |

样例基线：`samples/packages/minimal` 提供一次模型调用，`complete` 展示嵌套参数、三种能力、资源读取及输出校验；CONFIGURATION.md 和 CONTEXT.md 说明配置与接口。模板说明已重建，表单和资源一致性生成仍按计划推进，不添加自动重试、包内业务图或包之间直接调度。

## 独立契约

现状：加载文件与 symbol，按内容摘要建立资源标识，可用于服务/容器端口；支持静态端口检查与运行时校验。当前没有语义版本和契约引用关系页面。

| ID / 优先级 | 改进及边界 | 交付物 | 完成标准 |
| --- | --- | --- | --- |
| C1 / P1 | 展示字段树、类型、必填、可空、约束及说明；明确其不可执行 | 契约预览与资源说明 | 用户能从契约确定合法输入，且不会尝试把契约当作节点运行 |
| C2 / P1 | 加线时解释不兼容原因并指明来源/目标字段 | 端口差异与转换指导 | 缺字段、类型不同、作用域不可见分别定位；不自动强制转换数据 |
| C3 / P2 | 记录资源被哪些草稿/实例引用，设计契约升级影响预览 | 引用关系及兼容性报告 | 能列出受影响服务；Python 自定义验证规则的等价性无法证明时明确报告 |
| C4 / P2 | 统一契约权威源与分发生成方式，再考虑友好的标识和版本元数据 | 生成约定及版本设计 | 分发副本可检查漂移；旧实例仍可加载原内容；不能仅按类型名称认定兼容 |

样例基线：`samples/contracts/minimal.py:Text` 展示最小边界，`complete.py:Input/Output` 展示嵌套、可空、枚举与跨字段验证。结构变更优先增加转换块，避免在连线中引入任意 Python 表达式。

## 实施顺序与依赖

先做 B1/C1/P1 的信息呈现，再做 C2/P2 的配置反馈；B2 必须明确临时资源生命周期。引用关系与版本影响 P3/C3 共享同一资源依赖索引。C4 的版本元数据需先确定兼容规则；B4 需先获得阻塞时间和任务耗时数据。

每项作为一个独立交付单元，用对应教学样例做局部手动验证与必要边界检查。不恢复本轮删除的历史替身平台或验收数据集。性能和并发工作以实际测量及产品需要启动。
