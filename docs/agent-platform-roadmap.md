# Agent Platform 产品定位与实施步骤

更新日期：2026-09-18。以用户最新确认的模型契约和脚本控制流程边界为依据。

## 产品边界

平台提供可组合的业务包、Python 通用块、独立契约、服务实例与运行记录。配置者定义完整流程、接线和执行边界；模型承担流程内约定的语义处理，输入输出均严格校验。

模型输出可包含契约声明的类型、枚举和业务字段。Python 脚本块读取这些数据，计算分支或循环的严格布尔条件；平台执行预先定义的下一步。模型不得编写或修改流程、脚本、接线或实例，模型输出不能被直接当作可执行配置。

例如：模型返回契约内允许的分类值，脚本检查分类并输出 bool，if/else 进入配置者已定义的处理分支。契约之外的分类、字段或类型应失败，不由平台猜测或自动补充流程。

## 第一步：桌面启动即持久化（已交付并验证）

桌面自动启动应用专用 PostgreSQL，内部生成连接和主密钥；适配器保存环境、加密凭据、资源源码、草稿、版本和运行历史；实例发布原子提交；重启将未完成任务标记为中断，不自动重放。任务页支持服务/状态筛选和分页列表，页面显示实际存储模式。启用方式及验收边界见 [持久化接入](persistence.md)。

验收包括源码文件删除后从快照重建、版本回退与编号连续、任务终态保留、未完成记录中断标记、凭据加密、数据库断连及单后端约束。已通过 10 项 Python 检查、4 项桌面生命周期检查及实际 Electron 启停验证；当前验收环境为 Ubuntu 24.04 / PostgreSQL 16.15。

## 第二步：契约与脚本编排体验（后续事项）

改善输入输出契约展示、脚本条件接线、节点配置和错误定位；帮助配置者理解模型字段如何经过脚本判断影响已定义的流程。延续现有 FlowDraft 协议和三类资源，不新增模型生成流程或实例的入口。

## 第三步：持续运行与扩展（后续事项）

完成备份恢复及引用安全清理后，测量队列等待、节点耗时与记录增长；再按实际负载确定队列上限、背压、租约和受控并发。权限、第三方代码沙箱、多 Agent、长期记忆和任务断点续跑需要独立需求，不由持久化隐式引入。

当前已安装并启用本地数据库，仍未交付跨平台安装包、备份管理或 LangGraph 检查点续跑。其他配置体验优化见 [产品细化计划](product-refinement.md)。
