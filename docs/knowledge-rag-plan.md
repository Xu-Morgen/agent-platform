# 文档管理、知识库与最小 RAG 实施计划

日期：2026-09-21。状态：实施中。K1 契约与代理协议已完成，后续阶段按表推进。正式接口见 [知识库接口](knowledge-api.md)。

本次授权范围：平台基础能力及默认可替换资源；不进行真实模型验收。离线材料位于 `artifact/负向样本（AI写作）`。黑神话业务实验另按其计划开展，不作为本次平台交付阻塞项。

## 1. 用户要求与责任边界

文档管理和知识库作为平台基础设置；如何读取、以什么方式读取、如何检索和组织上下文由用户通过现有资源自行实现。RAG 始终由**独立契约、通用块和 Prompt 业务包**组成，平台仅提供最小标准化实现，不增加第四类资源、专用 RAG 节点、独立 RAG 执行协议或模型自主工具调度。

| 归属 | 负责内容 | 不承担内容 |
| --- | --- | --- |
| 平台基础能力 | 知识库和文档管理、不可变文档版本、受控读取、分页与大小边界、任务引用与证据持久化 | 不替用户决定解析器、切分、检索排序、上下文拼接及业务答案 |
| 独立契约 | 文档引用、查询、片段、证据集合、出题需求和结果 | 不执行读取或检索 |
| 通用块 | 调用基础读取接口，解析/分段/检索/排序/截取上下文、校验引文 | 不直连平台内部数据库，不绕开平台接口访问私有存储 |
| Prompt 业务包 | 查询理解、语义处理、基于证据生成、审查 | 不自行执行 I/O，不声明自定义执行入口，不修改流程 |
| 服务实例 | 固定上述资源与配置，编排检索、生成、判断与有限修订 | 不接收模型生成的流程配置 |

平台默认实现也必须是可查看、可替换的普通块/包/契约，用户可替换整个读取和检索流程。无需 RAG 的服务不必配置知识库。平台内部 PostgreSQL 继续由桌面管理，不增加用户数据库连接配置，不把知识库功能等同于业务数据库访问。

## 2. 当前基础与缺口

已有 [任务文件与 BlockContext](platform-runtime-files.md)、[资源开发协议](external-development-guide.md)、严格 NodeInput、实例快照、任务记录和固定服务组合。现有 TaskFile 绑定单次任务，不能直接当作跨任务知识库；现有文件副本、校验和子进程能力可以复用，但知识库归属、文档版本、读取接口和页面均需新增。

已有全文出题资源可用于提炼 DOCX 读取能力，不能把其中固定三题和业务状态放进平台。当前没有知识库检索或向量存储交付；本计划不要求先建设 embedding 连接、向量数据库或索引管理框架。

## 3. 平台提供的最小基础能力

### 3.1 文档与知识库管理

首版支持知识库创建、重命名、归档，文档批量导入 DOCX、列表分页、基本元数据、版本查看、替换及移出知识库。原件由平台保存，文件移动不影响副本；文件摘要用于完整性和版本识别，不引入任务去重语义。

文档 ID 表示逻辑文档，版本 ID 表示不可变文件内容。知识库修订标识固定成员及其文档版本；上传新版本、增删成员生成新的知识库修订。批量导入逐文件展示结果，失败项不能冒充已入库。

区分“原件可读取”和“某个解析/检索实现已处理成功”。首版默认实现不建立持久化索引，因此不把上传成功标成“索引就绪”。若后续用户提供索引实现，其状态属于该实现及对应版本，不能冒充所有检索策略通用状态。

平台页面至少提供知识库范围、文档版本、大小、摘要、导入错误和原件获取；正文预览通过最小读取块或配置者选择的读取服务产生，并注明解析资源版本，不另写一套隐藏解析器。历史任务可查看实际采用的证据文本与定位信息。

### 3.2 标准读取接口

以平台受控接口提供：解析知识库引用为固定修订、分页列出固定修订成员、按文档版本获取元数据和原件、登记任务实际采用的证据。接口须有严格请求/响应契约、明确不存在/归档/超限/损坏错误。

通用块仍只有现有 `api`、`context` 注入参数。首选在 `BlockContext` 扩展最小知识库访问方法，并通过父进程代理，沿用任务归属、取消和记录管理；正式方法名、同步/异步语义及子进程协议变更在 K1 定稿。不能把数据库对象、平台主密钥或任意文件路径交给资源。外部知识库可继续使用现有 API 块接入。

原件读取返回受当前任务约束的文件引用/只读路径能力，业务契约只传版本引用，不传平台绝对路径。分页响应和文件大小有边界，超限明确报告；限制参数由配置者确定，不任意扫描整个数据目录。

### 3.3 任务一致性和保留

首版由服务输入中的标准知识库引用选择知识库；提交时把“当前修订”解析为固定修订，保存任务实际绑定。知识库内容更新不改变服务实例版本，资源与检索配置变更仍生成新实例。排队和运行任务继续读取已固定的版本。

移出文档仅影响新修订和新任务；被历史/在途任务引用的文档版本与证据不能级联删除。首版归档和逻辑移除即可，物理清理后置并明确磁盘占用，不能借此扩大为完整缓存治理项目。

任务记录保留查询、知识库修订、实际候选及选用证据、读取/检索资源版本与参数。固定证据用于追溯，不承诺模型再次调用输出相同，也不构成断点续跑。

## 4. 最小标准 RAG 实现

### 4.1 首版流程

```text
业务查询及固定知识库引用
  → 列举文档块
  → DOCX 读取与段落定位块
  → 关键词/词面匹配检索块
  → 有界证据整理块
  → 基于证据的业务包
  → 引用与业务结果核验块
```

首版采用可解释的词面匹配基线，不引入向量依赖；中文分词/短语匹配的具体实现、评分规则和限制在 K3 通过真实文档确定，不能以“关键词检索”名称代替质量验证。少量资料允许按任务读取解析，但必须记录实际扫描范围；超过扫描上限明确返回范围受限，不能把未扫描内容断言为不存在。

默认读取块输出文档版本、解析器资源身份、段落/文本位置及正文。DOCX 无稳定页码时使用段落或规范化文本行号，不伪造页码。分段、片段长度、查询处理、排序、topK 和上下文总量均由资源契约、上游业务数据或既有节点配置表达；不为 RAG 单独发明参数体系，也不悄悄给普通块新增一套 Config 协议。

### 4.2 证据契约与可替换性

建议的标准证据条目至少包括：知识库修订、文档 ID/版本、片段 ID、正文、原文定位及读取实现身份。最终逐题引用必须指向本次选用的证据，原文可回查；排序分数可为辅助信息，不作为事实正确率。

正文规范化必须由解析块声明并固定版本；引文校验基于该版本的规范化原文，保留对应片段及摘要。不能拿不同解析器生成的行号互相核验。

用户可以替换 DOCX 解析、读取全文或局部段落、关键词或自建向量检索、外部搜索、重排和上下文整理，只需输出兼容契约；不兼容时加入显式转换块。新增读取算法不要求修改编译器，新增私有存储不要求开放平台数据库。

平台不强制用户采用默认片段算法或默认检索流程。未来索引若确有需要，应先用现有块/API 和明确契约验证；持久化索引作为派生数据必须记录文档版本和算法版本，不能以本计划名义先建设通用向量平台。
