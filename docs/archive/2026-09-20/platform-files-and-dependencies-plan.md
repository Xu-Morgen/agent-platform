# 平台改造计划：依赖、模型下载和任务文件输入

> 归档说明（2026-09-20）：本文件保留实施方案及当时的验收记录，当前使用以[平台运行说明](../../platform-runtime-files.md)和[文档出题说明](../../../examples/document-question-generation/README.md)为准。归档不代表真实线上模型与人工质量验收已完成。

日期：2026-09-20。状态：已实施，已通过本地自动验收及真实 OCR 小样本验收。配套：[文档出题实例计划](document-question-generation-plan.md)。

## 目标与边界

根据通用块 Python 文件声明的 dependencies、依赖下载来源和小模型地址，自动准备执行环境；任务页面支持选择并保存 PDF/DOCX，再通过契约向通用块传递文件引用。

仍只有业务包、通用块、契约三类业务资源。依赖环境、模型缓存和任务文件属于平台运行数据，不增加第四类业务资源。文件选择在提交任务之前完成，后台通用块不弹出选择窗口。

本期以当前支持的本地桌面环境为准，不承诺 Windows 原生安装、任意系统库自动安装或远程执行。本计划已实施。依赖及模型的真实下载/安装已在用户明确授权后于 `/tmp/agent-platform-ocr-runtime` 独立目录完成，未向主程序环境安装 OCR 依赖。

## 当前缺口

- `desktop/renderer/index.html` 的任务输入是 JSON；原生路径选择仅面向三类资源。
- `src/agent_platform/blocks/single.py` 已有 `dependencies: list[str]`，尚无完整自动准备环境与模型缓存能力。
- 通用块可能在文件顶部导入第三方库，不能先执行源码再发现所需依赖。
- 新能力需保持严格契约、实例快照、任务持久化、预算和取消语义。

## P1：定义声明和文件契约

1. 保留 dependencies，补充依赖来源与模型清单。拟议字段如下，实施时统一名称、生成 Schema 和示例：

   | 声明 | 内容 |
   | --- | --- |
   | dependencies | Python 包和版本要求，正式交付使用经过验证的版本 |
   | dependencySources | 软件源地址，或指定包的 wheel 下载 URL；直接下载文件附 SHA-256 |
   | models | 模型名称、版本、下载 URL、SHA-256、目标文件名 |

2. 将声明放在可静态读取的位置，AST 仅读取约定的字面量，不执行源码获取元数据，不支持任意安装脚本或 shell 命令。
3. 首期模型按独立文件下载，不自动展开任意压缩包。下载凭据由平台环境管理，不写进块源码；无鉴权的固定 HTTPS 地址作为首期验收入口。
4. 平台统一准备依赖及模型，通用块任务函数不调用 pip、不自行下载模型。OCR 库使用平台提供的显式模型路径。
5. 定义通用文件引用契约：文件标识、原始名称、实际格式、大小、内容摘要。平台验证文件可用性，不将任意本机路径当作已上传文件。
6. 输入契约通过明确的文件字段标注驱动页面文件控件；保留其他字段的 JSON 输入，不按“出题”服务名称硬编码页面。

交付：声明规范、文件引用契约、校验器、文档与示例。

## P2：自动准备依赖和小模型

加载通用块时执行“静态读取 → 校验声明 → 锁定依赖 → 准备环境 → 下载模型 → 导入与验证”，就绪后才允许运行。

1. 使用平台管理的独立 Python 环境，不往主程序环境直接安装 OCR 库。环境与平台 Python/SDK 版本匹配，按运行时、平台架构及依赖锁定内容计算缓存标识。
2. 锁定直接及传递依赖的精确版本、来源和可用制品摘要。依赖冲突、无匹配 wheel、缺系统库或需要未支持的源码构建时明确报错，不自动改系统配置。
3. 模型按内容摘要缓存。下载到临时文件，校验后原子启用；已有文件也校验，损坏后重新下载。依赖和模型准备使用互斥控制，避免并发破坏缓存。
4. 支持连接/下载/整体超时和手动重试；分别报告地址失效、网络异常、磁盘不足、摘要错误和依赖冲突。
5. 页面展示检查、下载、安装、验证、就绪或失败，展示来源、已下载量与可获得的总量，支持取消；不虚构进度百分比。
6. 加载通用块即按声明自动准备，不为每个依赖反复弹窗；准备工作不计入业务包 loop，也不消耗契约失败重试次数。
7. 缓存完整且可用时允许离线执行，缺失文件且离线时准确报告缺项。

交付：从声明到就绪的自动准备闭环，具备失败重试、取消和缓存复用能力。

## P3：在对应环境中执行通用块

独立环境不能只创建不用；这一步是平台改造的主要工作量之一。

1. 通用块由对应环境中的 Python 子进程执行，通过有版本的 JSON 消息传递输入、输出、进度和结构化错误。
2. 契约导出也在正确环境中完成；主平台执行静态兼容检查，子进程用真实 Python 契约执行运行时校验，不能仅凭 JSON Schema 代替自定义校验器。
3. 提供受控执行上下文：根据文件标识获取任务文件，根据模型名称获取只读路径；这些运行路径不进入业务契约。已有 API 块仍通过平台管理的连接访问外部服务。
4. 转发取消、超时及退出信号，CPU 密集型 OCR 不阻塞平台事件循环；必要时终止工作进程，停止后续页面处理，不返回伪成功。
5. 任务执行前检查环境和文件是否就绪；缓存丢失时重新准备，准备失败则明确终止。
6. 实例快照记录依赖锁定内容、模型清单和摘要；新块或新版本不得覆盖旧实例所用环境。被实例引用的缓存不能自动清理。

交付：环境真正用于执行，严格校验、取消、快照与缓存管理形成闭环。

## P4：任务文件选择、上传与保存

1. 任务页根据契约提供 PDF/DOCX 选择控件，显示文件名、大小、保存状态，支持替换和移除。
2. 本地桌面用原生文件选择和 IPC 流式复制文件到平台管理目录，避免二进制放进 JSON；API 调用提供上传接口，返回同一文件引用契约。
3. 校验扩展名、内容格式和可配置大小上限。读取通用块进一步检查文件损坏或加密；文件标识不能绕过路径边界读取任意文件。
4. 保存完成才可提交任务；页面根据契约生成文件引用输入。选择成功不等于文件已经保存成功。
5. 文件副本绑定具体任务，不写入服务实例配置；原文件移动或删除不影响已保存任务。文件引用及任务关联持久化。
6. 明确未提交文件过期清理、历史任务文件保留策略；失败上传仅留下可清理的临时文件，不产生完整记录。
7. 区分取消选择、不可访问、格式不支持、超限、保存失败和文件已删除等错误。

交付：用户选择文件即可调用服务，无需手写本机路径 JSON。

## P5：联合验收

- 全新环境可根据声明自动安装、下载、初始化；重复加载复用缓存，预置完整缓存后离线可用。
- 错误地址、下载中断、摘要不符、损坏模型、磁盘不足和依赖冲突均可定位并重试。
- 并发准备不破坏缓存，取消准备/任务可停止实际工作；OCR 不冻结页面。
- PDF/DOCX 上传成功后可调用，应用重启与原文件移动后平台副本仍可访问。
- 原有 JSON 任务、API 通用块、严格契约、预算和取消行为无回归。
- 依赖/模型更新可追踪，已有实例不被原地升级；真实 OCR 小样本端到端验收通过。

顺序为 P1 → P2 → P3 → P5；P4 可在 P1 的文件契约确定后独立推进，并在 P5 汇合。具体库版本、模型地址与摘要在实施时核对官方来源固定，不在计划中猜测填写。
