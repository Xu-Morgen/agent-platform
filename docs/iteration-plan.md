- 版本：0.1

- 状态：开发计划，所有实现迭代尚未开始

- 技术依据：[架构设计 v0.1](architecture-design.md)

## 1. 交付原则

首期同时交付桌面服务平台和示例业务产品。包模板从第一轮形成，完整实例流程独立于包；不能直到平台完成才验证包协议。每轮完成可运行的增量及相关验证，不以目录、接口占位或模拟成功替代实现。

需求编号沿用 P01—P09。技术选择可通过早期验证调整，已确认的产品行为必须保持。当前文档不代表依赖已安装、界面已实现或代码已通过验证。

文档编写与轻量检查已获本次任务授权；后续依赖安装、权限调整、重型测试、打包或发布仍按 [协作约定](../AGENT.md) 单独处理。本计划不自动执行这些操作，也不设缺乏工作量依据的日历承诺。

## 3. I1：运行骨架、契约与最小模板

### 目标

建立可启动、可退出的桌面宿主和 API 服务，通过最小包／实例样例证明边界可实施，提前验证可能影响架构的技术点。

### 工作项

| 编号 | 工作 | 交付与完成条件 |
| --- | --- | --- |
| I1-01 | 确定兼容依赖与工程入口 | 在获得依赖安装授权后落地项目元数据、锁文件和源码启动说明；不生成发布产物 |
| I1-02 | Qt 主线程与后台 asyncio 生命周期 | 打开最小窗口，API 健康检查可用，退出后后台服务不残留 |
| I1-03 | 契约基类和错误结构 | 严格模型、未知字段拒绝、嵌套路径错误、Schema 导出来自同一来源 |
| I1-04 | 包与实例协议模板 | 可加载包清单、输入输出模型、配置与实例流程；至少一包一配置 |
| I1-05 | 内存仓储及代码快照验证 | 从内存独立命名空间加载两个内容版本，改动源文件不改变已加载版本 |
| I1-06 | 传输与计量适配器验证 | 可控延迟服务验证连接可被桌面退出中止；定义严格 token 能力检查与非严格估算接口 |

### 验收

- 模板实例通过平台上下文调用模板包，输入输出错误能被拦截；包不包含完整实例流程。
- 公共 Schema 与运行时模型一致，数字字符串不能静默转成数字，未知字段有具体路径。
- 退出桌面程序能结束本地模拟长请求和后台循环；此阶段不调用付费模型即可验证生命周期。
- 两版代码可并存且分别执行原行为；技术验证失败先调整加载设计，不继续堆叠版本功能。

## 4. I2：配置中心、版本快照与回退

### 目标

完成用户可操作的环境配置与服务配置页面，建立稳定服务标识及完整版本历史。

### 工作项

| 编号 | 工作 | 交付与完成条件 |
| --- | --- | --- |
| I2-01 | 环境配置及凭据引用 | 模型/API 连接、超时、适配器能力，凭据不回显不记录到普通日志 |
| I2-02 | 多包、多配置表单 | 按命名作用域呈现契约、预算及绑定；冲突字段与缺失依赖不能保存 |
| I2-03 | 保存校验及完整快照 | 入口、流程、包、资源、契约、通用块版本及配置内容固定，保存失败不切换当前实例 |
| I2-04 | 稳定入口和版本编码 | serviceId 不随更新变化，major/minor 与 changeKind 可读，新版本立即成为当前实例 |
| I2-05 | 历史列表及回退 | 选择历史实例，验证当前环境后切换；退役实例不可直接调用 |
| I2-06 | 环境更新原子边界 | 预置任务占用接口，与 I3 的提交事务衔接；独立环境可修改，实例版本不变 |

### 验收

- 一个实例组合两个模板包与两份配置，页面能显示绑定归属，实例流程能引用二者。
- 保存缺依赖或无效配置失败，已有当前版本继续可用。
- 修改源脚本、Prompt 和包文件后，历史快照保持原内容；回退可恢复对应行为。
- 更新后旧 instanceId 被拒绝作为直接调用目标；激活旧版本后稳定服务入口指向该原实例。
- 回退后再修改不会复用已有版本号；环境更新不改变实例版本。
- 退出再启动后历史、环境及服务配置清空，不错误显示磁盘历史。

## 5. I3：异步任务、实例流程与平台能力

### 目标

从稳定入口提交任务，按固定实例快照执行通用块和业务包，返回经过校验的结果或错误。

### 工作项

| 编号 | 工作 | 交付与完成条件 |
| --- | --- | --- |
| I3-01 | 提交与队列 | 原子解析实例、校验输入、固定环境并登记占用，202 返回 runId 后独立执行 |
| I3-02 | 实例运行上下文 | 业务步骤、包调用、通用块与 API 调用通过平台接口，记录 stepId 与 attempt |
| I3-03 | Python 通用块 | 代码注册、绑定、双向校验、固定 LMS 解包成功与失败样例 |
| I3-04 | 模型/API 适配器 | 异步传输、超时、认证引用、脱敏错误、结构校验；不自动重试或修复输出 |
| I3-05 | 状态及结果接口 | queued/running/completed/failed，结果仅在完成后可取；记录不存在明确返回 404 |
| I3-06 | 桌面任务面板 | 输入样例、提交、状态、阶段、实际版本、错误和报告查看 |

### 验收

- HTTP 提交连接结束不影响执行；相同输入提交两次产生不同 runId。
- 更新或回退服务时，队列中和执行中的任务仍使用接受提交时的脚本、包、配置和环境。
- 模板实例依次调用两个包，平台核心不出现对应业务分支。
- LMS 成功码提取 bizData 并按目标契约验证；失败保留可用上游错误字段，不产生空成功结果。
- 模型输出缺字段、类型错误或无法解析时任务失败；最终实例报告还要单独校验。
- Schema 查询后版本变化，携带 expectedInstanceId 的提交返回明确版本冲突，不静默执行另一契约。

## 6. I4：取消、退出、环境一致性与预算

### 目标

完成首期必要的终止行为与预算控制，达成平台产品 M1。优先使用可控传输和计量替身验证竞态，再验证实际适配器。

### 工作项

| 编号 | 工作 | 交付与完成条件 |
| --- | --- | --- |
| I4-01 | 取消语义 | 排队取消、LLM 取消等待标记、完成竞争及幂等终态查询 |
| I4-02 | 错误优先及清理 | 取消等待超时／传输错误记 failed，原错误保留，释放环境并恢复实例就绪 |
| I4-03 | 桌面退出 | 停止受理与队列，立即停止本地模型传输，不沿用主动取消等待逻辑 |
| I4-04 | 环境占用互斥 | queued/running/取消等待均阻止相关环境提交修改，终态释放，无关环境不受影响 |
| I4-05 | loop 预算 | 包调用尝试开始计数；失败及显式再次尝试均计数；普通节点不计数 |
| I4-06 | token 预算 | 局部与全局账本、严格模式预留和核销、非严格估算、使用来源展示 |
| I4-07 | 状态检查统一入口 | 每次任务／流程状态变更前检查，预算不能阻断终止清理；最后一轮可正常完成 |

### 必须覆盖的边界

| 场景 | 预期 |
| --- | --- |
| 排队任务取消与调度同时发生 | 原子决定是否开始，不能既取消成功又启动调用 |
| 取消等待时 LLM 正常返回 | cancelled，不发布报告，不启动后续包 |
| 取消等待时超时／传输失败 | failed，保留具体错误及取消记录 |
| 终态提交前已受理取消 | 不得变为 completed |
| 已结束任务再次取消 | 原终态不变 |
| 任务失败／取消 | 临时上下文释放、实例可用，已有外部操作不回滚 |
| 旧任务结束时其实例已退役 | 实例仍退役，不能直接接新任务 |
| 环境更新与任务提交竞争 | 更新先成功则任务固定新环境；提交先成功则更新被拒绝 |
| loopLimit=1，首次包调用失败 | loopsUsed=1；显式第二次尝试被预算拦截 |
| loopLimit=1，首次包调用成功 | 允许报告组装并 completed，不因恰好到上限而失败 |
| 两个绑定各调用一次 | 局部账各为 1，全局账为 2；全局上限也生效 |
| 严格 token 额度不足 | 请求前拒绝，不能靠请求后才报错作为严格保证 |
| 严格模式遇不支持的模型适配器 | TOKEN_ACCOUNTING_UNSUPPORTED，不自动切到非严格 |
| 非严格模式单次响应超额 | 下一状态检查失败，记录实际／估算用量，不发布成功结果 |
| token 刚好用满且无后续消耗 | 允许最终校验和完成 |
| 退出桌面程序时有在途模型请求 | 本地连接中止，后台服务退出；重启 runId 不存在 |

## 7. I5：查重示例与完整交付

### 目标

交付能复用的标准模板、语义交互包和完整查重实例，完成 M2，并回归平台关键闭环。

### 工作项

| 编号 | 工作 | 交付与完成条件 |
| --- | --- | --- |
| I5-01 | 文本契约和清洗 | 非空目标、非空对照数组、按非空行分段、NFC 与空白处理，规则固定且可读 |
| I5-02 | 定量业务模块 | 完全相同段落计分、分子分母、匹配索引和 method；放在实例业务目录 |
| I5-03 | semantic 包 | Prompt、结构化模型输出、对照索引完整性校验与预算字段 |
| I5-04 | 查重实例流程 | 输入→清洗→定量→语义包→最终报告；两类报告均成功才完成 |
| I5-05 | 模板与接入说明 | 从模板构造新包和实例，不修改平台核心；说明源码加载、配置、预算和依赖要求 |
| I5-06 | 合成文本验收 | 约 1500 字目标与 6 篇对照，实际模型生成定性报告，保存脱敏验证记录 |

### 验收

- 定量样例可复现：完全一致得 1、无匹配得 0、目标两等长段落只匹配一段得 0.5；对照重复段落不放大分值。
- 空白目标、空数组、空白对照及错误数组元素均返回对应字段路径。
- 定性报告缺失对照索引、索引重复或越界时失败，不以填空修复。
- 正常 1 对 6 样例同时返回真实计算的定量结果与实际模型生成的定性结果。
- 模型超时、预算不足或输出不合规时失败，不返回仅定量报告冒充完成。
- 不输出最终抄袭布尔值，不评估语义准确率，不接入学生身份、真实 LMS 或数据库。

实际模型端点与凭据属于验收环境输入。若暂不可用，明确记录真实模型验收未完成；替身可验证契约与流程，但不能据此宣称 M2 完成。

## 9. 首期完成标准与后续边界

首期完成必须同时满足：

- 桌面程序能配置环境、组合包与配置、保存实例并通过稳定入口调用。
- 同次运行期间完整历史可回退，退役实例不能被绕过入口直接调用。
- 严格输入输出、明确错误、loop/token 限额、取消和退出行为全部按契约执行。
- 标准模板、包协议与实例样例可复用；查重产品完成实际模型的功能样例。
- 启动及接入说明与实际实现一致，明确首期内存丢失边界及未实现能力。

数据库版本再处理历史版本跨重启保存、任务记录持久化和恢复规则；权限、性能优化、通用防御、复杂重试、包市场、沙箱、多 Agent、可视化画布及复杂查重规则均不计入首期完成条件。
