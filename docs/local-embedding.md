# 本地 embedding 与语义检索

2026-09-22 已交付 Linux x86-64 / Python 3.12 的本地 CPU 模型导入、默认选择、任务固定模型、受控语义搜索和任务内缓存。实际验收使用 BGE-small-zh-v1.5 的 Xenova ONNX 转换，详见 [制品与依赖](../resources/embedding/README.md) 和 [验收记录](archive/2026-09-22/local-embedding-validation.md)。

## 导入和选择模型

1. 准备模型目录：包含 `embedding.json` 和清单声明的 ONNX、tokenizer JSON、配置 JSON。已验证清单在 [resources/embedding](../resources/embedding/README.md)，需使用完全一致的文件摘要、依赖及适配参数；单独权重文件不能导入。
2. 打开「平台设置 → 本地 embedding 模型」，选择目录，点击「检查并导入」。页面依次展示摘要检查、复制和 CPU 小样例检查；成功后显示模型内容身份、大小、格式及就绪状态。文件复制到应用目录，之后移动原目录不影响运行。
3. 在列表中选择模型并保存默认选择。对新提交任务立即生效，不需要重启，也不生成服务实例版本；已经提交的任务继续使用固定身份。
4. 可点击「验证所选模型」查看真实维度、有限数值校验、加载/推理耗时和进程峰值内存。结构及编码检查不等同于语义质量验收。

导入不会执行模型目录中的 Python、安装清单依赖或联网下载。运行依赖由平台安装环境提供；不兼容会显示明确错误。没有就绪默认模型时，语义任务不能受理；运行时文件损坏也会失败，不回退远端模型或词面检索。模型版本不可原地覆盖，没有物理删除入口。诊断失败可标记模型不可用；文件损坏时应恢复原文件或导入另一身份的完整制品。

## 配置普通检索服务

在服务页加载 [默认 RAG 资源](../resources/rag/README.md)，按以下顺序组合：

`列举知识库文档 → 读取 PDF/DOCX 正文 → 本地语义检索 → 整理并登记证据`

使用当前 `rag-read-docx@3.0.0` 读取块时，还须在平台设置导入并选择就绪的 OCR 模型组合；即使只读取 DOCX 或纯文字 PDF，任务提交也要求固定该模型。OCR 推理仅在需要时发生，见 [OCR 前置条件](local-ocr.md#导入与更换)。

输入选择 `RetrievalRequest`，输出选择 `EvidenceContext`。四个块的高级参考设为空列表，无需绑定聊天模型或配置 LLM 预算。本地检索块是 `resources/rag/blocks/semantic_search.py`，保持 `ParsedCorpus → SearchResults`；替换现有词面块后通过页面保存新实例，既有实例与任务不变。

任务页填写 query 并选择知识库，可在 limits 设置 topK、读取范围及片段上限。默认语义块不使用词面 terms，也不混合词面分数；会按固定 tokenizer 再切分超长片段，定位追加原片段内的零起算半开区间 `chars[start:end]`。无法保留定位、切分超过 maxFragments 或查询过长时明确报错，不静默截断。默认没有最低分阈值；自定义普通块可在 SDK 请求设置 minimumScore。

检索结果按归一化向量余弦相似度降序排列，同分保留片段顺序。topK 仅代表相对接近，分数不是事实可信度，不能与词面分数直接相加。无关问题也可能有候选；下游必须继续检查资料是否足够。需要生成答案或审题时，仍由独立 Prompt 包负责。

## 生命周期与限额

- 提交固定知识库修订和完整模型清单；顶层及固定子服务共用本任务模型。默认选择、知识库更新只影响新任务。
- 向量驻留任务独占工作进程，同任务跨节点、循环、契约重试复用已完成片段；不同任务不共用缓存。缓存身份包含模型、文档版本、解析/切分身份、正文摘要及用途。
- 同时一个模型进程，推理线程 2、批次 8。容量等待和每次工作进程请求各最多 120 秒；等待时不加载模型。模型进程虚拟地址空间上限 3 GiB，单任务最多缓存 2000 个不同片段。
- 单次最多 500 片段、一百万字符、topK 100；单任务最多 200 次搜索/切分请求、100 条搜索记录。默认块还有服务输入的更小限额。超限报错，不裁减请求后返回成功。
- 本地处理 token、批次、缓存命中及耗时独立记录，不计远端收费 token 或 Prompt loop。主动取消、失败和应用退出清理进程与向量；不支持任务续跑。

历史页面保存固定模型、查询、候选、证据、范围与统计，不保存向量。重启恢复历史，未结束任务按 APPLICATION_INTERRUPTED 处理；没有声称可以逐位重现原排名。

模型文件位于应用 `storage/embedding-models/`；元数据与默认选择在 PostgreSQL。备份应包含完整 storage 目录。开发用 `--memory` 的模型副本、选择和记录仅保留本次会话，退出清理。

首版不含 GPU、远程 embedding、TaskFile 语义搜索、向量数据库、跨任务索引、模型自动转换或下载、模型物理删除和自动文档同步。真实检索验证覆盖少量合成资料；大规模质量、其他模型组合和跨平台运行尚未验证。

资源开发者参见 [权威契约及 API](local-embedding-contracts.md)。
