# 三类资源专项优化计划

基线：2026-09-17 用户确认的 V1。2026-09-18 已将业务包收敛为声明式 Prompt 包；下表中的后续体验事项仍待实现；当前指导样例见 [资源手册](resource-guide.md)。保留 block、package、contract 三类资源，暂不引入新插件协议或资源市场。

## 通用块

现状：一个 Python 文件、一个入口，严格输入输出、依赖检查、内容快照；支持清洗、转换、判断和计分。业务参数通过上一层完整输出提供；声明 API 能力的块在节点表单绑定 API 环境并填写请求路径 api.path，不需要模型预算。路径随实例快照保存，同一块的不同节点可以使用不同路径。

| ID / 优先级 | 改进及边界 | 交付物 | 完成标准 |
| --- | --- | --- | --- |
| B1 / P1 | 块卡片展示用途、字段说明、支持的输入形态；区分转换块和判断块 | 目录卡片与输入输出帮助 | 无需打开源码即可找到字段转换和严格 bool 条件块 |
| B2 / P1 | 增加一次执行预览；优先复用纯块临时服务/任务语义，明确会执行代码 | 输入表单、输出/错误预览及临时资源清理 | 成功显示输出；错误定位字段；不切换用户已有服务版本 |
| B3 / P2 | 加载错误细化、依赖兼容提示、重新加载时明确版本冲突 | 可操作的修复指引 | 缺依赖、重复入口、类型错误和相同版本内容变化均有具体解释 |
| B4 / P2 | 明确耗时块的执行边界；测量后再引入受控进程执行 | 超时/取消协议及运行记录 | CPU 密集块不长期阻塞 API；退出不会遗留任务，不能简单用线程宣称可强制取消 |

样例基线：`samples/blocks/minimal.py` 展示最小入口出口，`complete.py` 展示节点 API 路径配置、查询、响应校验、嵌套输入、枚举、默认值和统计输出；README 说明配置步骤、bool 条件及错误处理方式。每类只保留最小和最完整两套示例，不再拆出 API 功能示例。块负责显式数据处理和外部查询，需要模型的处理通过业务包表达。

## 业务包

现状：清单、Prompt、严格输入输出与可选参数模型、内存内容快照；平台标准入口统一调用模型。同包不同节点独立选择模型和预算，包只可提供预算默认值，数据处理全部由通用块节点完成。

| ID / 优先级 | 改进及边界 | 交付物 | 完成标准 |
| --- | --- | --- | --- |
| P1 / P1 | 参数表单覆盖嵌套对象、枚举、描述、默认值与必填；配置预检反馈靠近字段 | Schema 表单与错误定位 | 同包两个节点独立编辑，保存/重开后值一致，不误覆盖另一节点 |
| P2 / P1 | 保存前说明模型连接、单次输出上限和全局/局部累计限制 | 能力摘要、预算解释 | 用户能理解单次请求可能超额及响应后的检查；循环预算累计方式清楚 |
| P3 / P2 | 展示包更新影响与实例配置差异，提示受影响节点 | 版本差异预览 | 新包只影响新保存实例；在途任务及历史快照继续使用原代码和资源 |
| P4 / P2 | 完善开发模板说明、输出契约提示和资源一致性生成 | 包开发模板和契约同步指引 | 复制包、改标识、加载、配置后可完成一次真实交互，失败无伪造结果 |

样例基线：`samples/packages/minimal` 提供一次模型调用，`complete` 展示嵌套参数、占位符和预算默认值；CONFIGURATION.md 和 CONTEXT.md 说明配置与接口。模板说明已重建，表单和资源一致性生成仍按计划推进，不添加包内业务图或包之间直接调度；运行时契约失败由流程执行器按服务 retryLimit 有界重试。

## 独立契约

现状：加载文件与 symbol，按内容摘要建立资源标识，可用于服务/容器端口；支持静态端口检查与运行时校验。当前没有语义版本和契约引用关系页面。

| ID / 优先级 | 改进及边界 | 交付物 | 完成标准 |
| --- | --- | --- | --- |
| C1 / P1 | 展示字段树、类型、必填、可空、约束及说明；明确其不可执行 | 契约预览与资源说明 | 用户能从契约确定合法输入，且不会尝试把契约当作节点运行 |
| C2 / P1 | 加线时解释不兼容原因并指明来源/目标字段 | 端口差异与转换指导 | 缺字段、类型不同、作用域不可见分别定位；不自动强制转换数据 |
| C3 / P2 | 记录资源被哪些草稿/实例引用，设计契约升级影响预览 | 引用关系及兼容性报告 | 能列出受影响服务；Python 自定义验证规则的等价性无法证明时明确报告 |
| C4 / P2 | 统一契约权威源与分发生成方式，再考虑友好的标识和版本元数据 | 生成约定及版本设计 | 分发副本可检查漂移；旧实例仍可加载原内容；不能仅按类型名称认定兼容 |

样例基线：`samples/contracts/minimal.py:Text` 展示最小边界，`complete.py:Input/Output` 展示嵌套、可空、枚举与跨字段验证。结构变更优先增加转换块，避免在连线中引入任意 Python 表达式。

## 实施顺序与依赖

先做 B1/C1/P1 的信息呈现，再做 C2/P2 的配置反馈；B2 必须明确临时资源生命周期。引用关系与版本影响 P3/C3 共享同一资源依赖索引。C4 的版本元数据需先确定兼容规则；B4 需先获得阻塞时间和任务耗时数据。

每项作为一个独立交付单元，用对应教学样例做局部手动验证与必要边界检查。不恢复本轮删除的历史替身平台或验收数据集。性能和并发工作以实际测量及产品需要启动。

## 服务配置中的三类名称（2026-09-18）

已统一业务包、通用块、契约的页面名称和加载说明；输入、输出、分支和循环的契约选择标明来源，左侧可查看已有契约及字段。页面解释先加载、再选契约和添加处理步骤的顺序，以及实际业务数据在任务调用时填写。按用户确认，本次不调整其他服务配置；无法归入三类的新内容先提问。

“加载本地资源”的本地路径支持系统选择窗口：业务包选择目录，通用块和契约选择 Python 文件；确认后回填路径并自动加载；契约缺少类名时提示补填后点击“加载资源”。取消选择保留原路径，也可手动填写。加载状态显示完整路径、成功名称或具体失败字段，区分路径不存在、无法读取、格式不符、缺少 package.json、Python 语法及契约声明错误；成功后刷新资源列表并清除搜索过滤。已完成脚本语法、IPC、页面加载逻辑及真实三类模板的轻量检查，系统窗口交互尚未在桌面手动验证。

## 完整数据传递与通用块转换

平台已移除字段选取、改名及拼装执行逻辑；业务包和通用块的输入输出契约由源码或清单固定声明，页面只读。普通步骤自动接收上一层完整输出，不再提供输入来源或 inputs 配置；分支、循环保留控制所需的完整数据配置。服务返回仅选择输出契约，自动使用最后一步的完整输出，不再提供返回数据来源或顶层 output 配置；空流程校验失败。契约不兼容会报错并提示通过通用块转换。已删除旧映射的页面修复入口、协议字段、历史实例兼容执行器及兼容测试；不提供兼容或迁移。流程编译器使用 flow-4，旧版本实例不能恢复，需按当前协议重新创建；不自动删除已有本地数据。

服务运行设置已增加 retryLimit（0～1000，默认 3）。运行时普通节点输出不符合自身或下一步输入契约时，下一步不执行，重新调用产生数据的上一步；每次尝试保留记录并计入预算，取消、预算耗尽或重试耗尽后停止。服务首个输入不合法以及传输错误不重试。
