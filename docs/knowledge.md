# 文档、知识库与最小 RAG

2026-09-21 已交付平台基础功能及默认可替换资源。知识库与文档属于基础管理；读取、检索和生成通过既有独立契约、通用块和 Prompt 包组织，仍使用 flow-6，没有新增 RAG 节点或资源类型。

## 管理 PDF/DOCX

1. 打开侧栏「文档与知识库」，填写名称并保存。可以重命名、归档及取消归档。
2. 选择多份 PDF/DOCX 批量导入，逐项查看成功或失败。同名文件创建不同逻辑文档；需要替换原文档时使用该文档卡片的「替换版本」。
3. 卡片显示当前版本、大小和 SHA-256，可查看所有历史版本并获取原件。文档列表每页 20 条；分页期间固定查看同一修订，刷新切到当前修订。
4. 移出文档只影响新的知识库修订；归档后不接受新任务和原件变更。已绑定任务继续使用旧修订，历史证据与原件仍保留。

原件保存成功仅表示已保存并通过上传格式检查，没有后台索引或“索引就绪”状态。每份原件最多 50 MiB，接受 PDF/DOCX；上传检查扩展名与文件签名，DOCX 另保留正文 XML 结构校验。PDF 完整结构、打开密码和页面可读取性由服务读取块校验，上传成功不保证解析成功。平台复制原件，之后移动原始文件不会影响保存的版本。

## 通过普通服务读取和检索

按 [默认资源操作手册](../resources/rag/README.md) 在正式服务页加载并组合资源：

- **正文预览**：准备文档预览 → 读取 PDF/DOCX 正文。两步均选择高级参考空列表，输入选择 `DocumentPreviewRequest`、输出选择 `ParsedCorpus`。保存后回到知识库页刷新并选择此读取服务，点击文档「预览正文」。结果注明文档版本、解析身份和 PDF 页码或 DOCX 段落及规范化字符区间，并作为普通任务保存。不依赖聊天模型；新版读取块须在平台设置选择 OCR 模型组合。下拉框只列出当前协议可执行、接受页面 `{knowledge, versionId}` 输入、返回正文片段且环境配置有效的服务；仅有一个时自动选中，没有时禁用预览并显示创建说明。出题服务和旧协议服务不会作为预览候选。
- **离线检索**：列举文档 → PDF/DOCX 读取 → 词面检索 → 整理并登记证据。输入选择 `RetrievalRequest`，输出选择 `EvidenceContext`。每步参考为空，无须配置聊天模型；新版读取块须先选择平台 OCR 模型。
- **本地语义检索**：将词面节点换为 `semantic_search.py`，在平台设置导入并选择本地 CPU 模型；任务固定模型，结束清理向量，不需要聊天模型连接。见 [使用说明](local-embedding.md)。
- **基于证据回答**：在检索之后接默认回答包和引文核验块；核验块参考生成时的 EvidenceContext。只给回答包绑定模型，模型不执行读取、检索或配置流程。

任务页根据 `TaskKnowledge` 契约标注自动显示知识库选择框，不依赖用户先在 JSON 中填写引用。输入区及服务样例只展示必填业务字段；例如三题出题只需填写 `requirement`，再在下方按名称选择知识库。提交时平台补齐引用并固定当前修订，必填知识库未选择时不能提交，粘贴 JSON 中的旧 ID 也不会替代选择控件。可选业务参数未填写时使用契约默认值。引用可嵌套在对象或实际数组中；需调用历史修订时使用 API 的显式引用，页面统一选择当前修订。未绑定的知识库不能由资源在运行中自行扩展读取范围。

默认资源的读取/返回限制在服务输入 `limits` 中设置，显式检索词在 `terms` 中设置。默认中文二元组/英文词基线可替换为 [完整短语检索](../resources/rag/alternatives/phrase_search.py)，无需修改平台核心。替换资源后通过页面保存新实例，旧任务和实例快照保留。

## 历史证据和一致性

提交任务固定知识库修订及对应文档版本；更新知识库不改变服务实例版本，也不影响排队或运行任务。任务详情显示本次查询、固定修订、实际候选及选用证据、扫描版本、限制参数、登记节点及源码摘要；选用证据可以获取对应原件。每个读取/检索步骤的输出与服务资源快照用于追溯具体实现。

接口结构严格校验，登记时另检查正文摘要、候选与选用一致性、版本归属和参数大小；引文核验检查精确引文属于本次选用片段。默认定位基于固定版本的规范化文本，不声称 DOCX 有稳定页码。平台不替用户验证自定义解析器的语义正确性，得分也不是事实可信度。

原件保存在平台数据目录 `knowledge-originals/`；元数据、修订、版本及任务证据持久化到现有 PostgreSQL 文档仓储。物理清理尚未实现，移除、归档及历史版本都会保留磁盘占用。备份应包含完整 storage 目录。`--memory` 仅维持会话，退出清理临时原件。

## 验证和当前边界

2026-09-21 基础阶段已验证：7 份用户指定 DOCX 的离线读取/检索；同名文件、损坏文件、替换、分页、归档、移出及旧原件；在途更新固定旧修订、新任务新修订；真实块子进程代理、取消和越权错误；PostgreSQL 停库重启及历史证据恢复；隔离 Electron 正式页面组装、保存、检索、预览及替换检索资源。未安装依赖，未调用模型。

扫描达到文档、字符或片段上限时明确标记 `scopeLimited`，无命中不代表整个知识库不存在答案。当前不做持久化索引、向量数据库、DOCX 页眉/脚注/图片读取或自动同步；PDF 扫描/混合页支持本地 OCR。正文预览显示普通服务返回的数据，未建设富文档排版查看器。大规模容量、索引治理、自动物理清理、跨平台桌面验收均未开展。

后续独立交付的[知识库三题业务](../examples/black-myth-rag-question-generation/README.md)已导入 7 份授权 DOCX，通过 20 次 ds 调用验证主路径、检索替换和资料不足；2026-09-22 人工验收通过。该实验未调用默认回答包，默认回答包仍只有加载和端口兼容检查结论。

开发者接口见 [知识库 SDK 与管理 API](knowledge-api.md)，实施记录见 [归档计划](archive/2026-09-21/knowledge-rag-plan.md)。

2026-09-22 本地 embedding 已通过真实模型、独立 Electron 页面、PostgreSQL 重启和四类合成问题对照验收，见 [结果与限制](archive/2026-09-22/local-embedding-validation.md)。模型及选择持久化，向量仅在任务内存；无关查询仍可能返回 topK 候选，不等于资料充足。


2026-09-22 新增 PDF 上传、跨格式版本替换、正确原件下载类型和任务副本后缀；默认读取块 2.0.0 支持文字层与扫描 PDF。升级步骤及边界见[默认资源手册](../resources/rag/README.md#pdf-支持与升级2026-09-22)。本次未自动改写正式服务快照，也未开展 PDF 出题真实模型验收。

OCR 管理及新版读取块 3.0.0 的使用见 [本地 OCR](local-ocr.md)。平台负责模型导入、更换和任务固定；旧服务须通过页面显式升级。
