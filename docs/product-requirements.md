## 1. 当前范围

配置者加载通用块、Prompt 业务包和独立契约，在服务页拼接顺序、条件及有限循环，配置节点后保存为实例，通过稳定服务入口调用、查询结果和回退版本。实例由平台生成，无需手写执行入口。

业务包只维护输入输出结构验证、可选参数和 Prompt；模型调用由平台统一执行，数据处理和转换使用通用块。samples 提供三类资源的最小/完整模板与配置说明，原查重产品已移除。

技术栈为 FastAPI + Pydantic + LangGraph，桌面端使用 Electron。桌面自动管理本地 PostgreSQL，首次初始化、启动就绪与退出停库均由程序处理，配置和历史跨重启保留；显式 --memory 仅供开发。实际验证范围与数据目录见 [接入说明](persistence.md)。

权限与多租户治理、业务数据库接入、任务断点续跑、传输自动重试、模型降级、自动修复输出、资源市场、第三方代码沙箱、多 Agent、RAG 和无限制自由画布均不在当前交付范围。后续优先级见 [产品细化计划](product-refinement.md)。

## 2. 概念与责任边界

| 概念 | 定义 |
| --- | --- |
| 业务包 | 可复用的 Prompt 与输入输出验证声明，可含业务参数和节点预算建议；由平台统一调用 LLM，不包含处理或转换逻辑 |
| 契约 | 可复用的输入输出类型与校验规则，用于服务和控制容器端口，本身不执行任务 |
| 环境配置 | 平台管理的模型连接、API 地址、认证引用及运行参数 |
| 服务配置 | 实例使用的一份配置单元，包括包参数、模型连接、环境引用及预算；一个实例可组合多份配置 |
| 服务实例 | 服务配置页完成拼图并校验保存后生成的完整可执行结果，固定流程、契约、模块内容和节点配置，拥有独立实例标识 |
| 服务草稿 | 尚在编辑的拼图与配置；允许暂时不完整，不可接受任务，也不属于可回退实例历史 |
| 业务包节点 | 业务包在流程中的一次放置，拥有独立节点标识、参数、预算与环境绑定；必需配置完成后才是合法节点 |
| 服务 | 拥有稳定调用入口，指向服务中心当前选定的实例版本 |
| 通用块 | 独立 Python 文件中的单一业务函数，声明输入输出和用途，作为可独立拼接的确定性节点 |
| 实例流程 | 组织业务包、通用能力及确定性业务计算的完整业务实现 |
| 运行任务 | 一次实例调用及其固定版本、输入、状态、结果与错误 |

服务配置中的资源名称统一为“业务包、通用块、契约”，不使用“模型交互”“处理模块”“输入数据结构”等名称指代资源。输入、输出及分支、循环的数据约束均称为契约，选择项注明来自哪个业务包、通用块或契约文件。实际输入数据在任务调用时填写；服务配置中的输入样例仅用于契约校验。此次仅统一三类资源相关表单，服务名称、版本、条件分支、循环次数等其他配置保持原样；后续遇到三类无法包含的内容，先向用户提问。

### 2.1 平台与包

- 平台负责配置页、环境管理、包挂载、实例版本、通用块注册与调用、模型调用、契约校验、任务状态和仓储记录。
- 平台根据服务拼图生成实例执行流程；通用块承载确定性处理，包负责 LLM 交互的输入输出契约和 Prompt。具体业务通过独立块与包接入，平台核心不包含查重算法或课程业务分支。
- 固定消息格式的解包、清洗与验证由 Python 通用块完成；例如判断哪个字段代表成绩等依赖语义的识别，由模型完成，并校验模型输出结构。
- 通用块本身是硬编码的确定性 Python 实现，不承载模型自主判断。实例流程将通用块与业务包组合使用。
- 包由平台标准入口执行模型调用，数据处理通过通用块节点完成；实例返回结果后由平台校验保存，不硬编码环境地址与真实凭据。
- 首期只加载受信任的本地包，不要求第三方代码沙箱。

### 2.2 权限的后续方向

权限验证保留为后续独立服务或流程接入能力，具体方案另行确定。当前不实现业务调用者权限检查。模型/API 的连接认证配置与业务调用者的权限验证是不同能力，前者仍在当前范围内。

## 3. 用户与主要路径

- 模块开发者：依照标准模板编写业务包和单文件通用块，声明契约并提供样例。
- 平台配置者：配置环境、挂载模块，在服务页拼图并配置各包节点，保存实例版本、查看历史和回退。
- 业务调用方：提供符合服务契约的输入，提交任务，查询状态与结果。

```text
环境配置页保存模型／API 环境，模块库加载业务包和单文件通用块
  → 服务配置页定义输入与期望输出，按顺序、条件或循环拼接模块
  → 点击业务包节点，在悬浮配置窗填写参数、预算并选择已保存环境
  → 检查所有入口／出口、流程完整性和节点配置
  → 成功保存，生成立即生效的完整实例及历史版本
  → 任务调用页或稳定 HTTP 入口选择服务，提交输入并取得运行标识
  → 执行固定实例，校验输出并返回结果或具体错误
```

挂载不自动执行业务操作。无效配置不得作为可调用实例生效；“保存后立即生效”指通过校验后的成功保存，无需另行启用。

## 4. 首期平台需求

### P01. 包加载与标准接入

- 读取本地包清单、版本、契约和 Prompt，检查占位符与输入输出结构；包无自定义入口或依赖声明。
- 同一包可被多个实例复用，也可在同一拼图中放置多次；各节点配置独立。模块加载不要求先配置运行环境，必需参数和环境在节点配置及实例保存时验证。
- 通用块加载时检查代码依赖、入口及契约；节点配置不完整或流程无效时给出具体原因，不生成可调用实例，允许继续编辑草稿。
- 提供可复用标准模板与接入样例，后续业务包依协议接入，不要求修改平台核心。

### P02. 服务配置页与环境配置页

| 页面 | 最小功能 |
| --- | --- |
| 环境配置页 | 配置模型连接、模型标识、凭据引用、API 连接及调用超时等必要参数，供服务配置选择 |
| 服务配置页 | 从模块库选择通用块与业务包，拼接顺序、条件和循环；通过节点悬浮窗依 Schema 配置业务包参数、预算及环境；完成后校验保存生成实例，展示标识与版本，查看拼图历史及回退 |
| 任务调用页 | 选择已保存服务及其当前完整实例，填写输入、执行、查询状态、取消和查看结果；不负责拼装流程 |

- 包通过 Schema 声明配置类型、必填项、默认值和说明。
- 凭据由平台环境管理，不写入业务包或日志。
- 保存校验失败时返回具体字段或依赖问题；成功保存后新实例立即可调用，不设置额外发布步骤。
- 首期必须提供参考 Scratch 拼接思想的流程编辑能力；不能仅展示 Schema 并要求手改完整实例 JSON。结构不匹配时由用户加入转换通用块，不自动猜测、重命名或强制转换字段。
- 服务配置采用从上到下的结构化流程图；模块可搜索并在指定位置或分支中插入。业务包和通用块的输入输出契约固定声明，普通节点 primary 来源自动确定；第一步为服务完整输入，后续为上一层完整输出。references 默认取上一节点主输入（首节点零项），高级设置替换为作用域内完整来源列表；服务返回仅配置输出契约，自动校验并返回顶层流程最后一步的完整输出，空流程不能保存为服务。不提供字段映射；字段选取、改名、合并和结构转换必须通过通用块完成，输入输出契约不兼容时校验报错，解释服务输入、节点输出及最终返回值，并展示字段类型和说明。
- 点击业务包节点打开悬浮配置窗，分别设置其参数、loop/token 预算及所需环境连接；同包不同节点相互独立。未配置完成时明确标记无效，不可保存为可调用实例。
- 服务草稿与实例历史分开；仅成功校验并保存的完整拼图产生新实例及历史记录。

### P03. 实例版本、稳定入口与回退

- 一个服务提供稳定入口，指向当前选定的实例版本；更新成功后入口原子切换到新实例。
- 旧实例退役后不能直接接受新调用；需要在服务中心选择历史版本并回退后，才能由稳定入口再次调用。
- 每次更新完整保留旧实例的完整拼图、编译信息、业务包／通用块实际内容、契约及配置，不能只保留原始文件路径或版本号。保存不可变快照，避免源文件后续修改破坏回退。
- 内存模式的历史限本次运行；PostgreSQL 模式保存源码内容及实例，支持重建记录与跨重启回退。
- 回退重新选用指定历史实例，不重新编造其版本；使用当前环境，回退前重新验证环境是否满足该实例要求。
- 包变更视为大版本更新；服务配置变更视为小版本更新；包与配置同时变更视为破坏性整体更新。流程、端口及通用块变化的版本归类由架构设计确定。
- 更新生成新实例标识，不原地修改旧实例。每次任务固定提交时的入口、流程、包、配置与实际环境设置，更新或回退不改变已经排队或运行的任务。
- 环境配置独立于实例版本。存在引用该环境的排队、运行或取消等待任务时，不允许更新环境；空闲时可更新，后续任务使用新环境，LLM 地址等环境变化不改变实例版本号。
- 具体版本编码由技术设计确定，需区分包更新、配置更新与整体更新。

### P04. API 接入与 Python 通用流程块

- 包只绑定模型连接，API 接入、清洗和转换等处理通过独立通用块节点组织。
- 通用块交付为单独 `.py` 文件，包含单一业务函数及输入输出声明、用途说明；类型／契约声明不算额外业务函数。无需为每个块另写目录清单或实例入口。注册时读取契约，不执行业务函数。
- 普通通用块无需环境。声明 API 能力的块在节点配置中选择 kind=api 的环境连接并填写请求路径 api.path；平台提供凭据、超时与响应校验，请求方法、参数生成和响应结构由块定义。路径不写死在可复用块中，随实例版本固定。包节点只接受 kind=model 的连接。
- API 块通过 NodeInput.primary/references 读取业务参数并生成请求，API 响应须按明确契约校验后才能传入下游。平台不再内置固定 LMS 响应解包，外部协议处理放在对应块中。
- API 块同样参与环境快照、任务占用与退出清理；单纯查询 API 不消耗模型 loop/token 预算。可运行模板见 [API 块说明](../samples/blocks/README.md)。

### P05. 严格契约与模型环境

- 用户输入、通用块输入输出、API 响应、LLM 输出、最终报告均执行相应运行时校验。
- 契约明确字段类型、必填项、范围、枚举、嵌套结构与未知字段处理方式。
- 从单一契约来源派生类型、校验规则与公开 Schema，避免手工维护多套规则。
- 校验失败指出阶段、节点、入口／出口、字段路径及具体原因，例如缺少必填字段、应为字符串、枚举不合法；连接错误同时指出两端。不得只返回“数据不符合契约”。错误信息须脱敏，不回显原输入或凭据。
- 拼接前检查出口契约是否满足入口契约；后端在保存时执行同等检查，不能只靠前端禁止拖放。运行时仍校验实际数据，不把静态可连接视为实际输出有效。
- 不通过强制类型转换、静默填值或自动兜底制造合规结果。
- 包定义 Prompt、输入输出契约及可选业务参数，可用 budgetDefaults 提供节点预算默认值；节点和任务管理并执行 loop/token 预算，平台统一管理连接、凭据、超时及模型调用。
- 模型输出结构校验与模型语义判断准确性是两件事。前者必须验收，后者首期不验证。
- 服务配置 retryLimit 为 0～1000 的整数，默认额外重试 3 次，0 表示不重试。仅运行时输出契约失败或下一步输入校验失败时重新调用产生数据的上一步，下一步在校验通过前不执行；静态契约不兼容阻止保存。次数耗尽保留具体错误和尝试记录。重试受调用预算、token 预算、取消及图步数限制约束；传输错误不重试，不提供模型降级或自动修改输出。

### P06. 任务状态、取消与关闭

- 提交后立即返回运行标识，支持查询状态与结果；执行不依赖提交请求的 HTTP 连接持续存在。
- 状态至少包含 `queued`、`running`、`completed`、`failed`、`cancelled`；取消等待期间需可识别，具体采用状态还是标记由实现确定。
- 根据存储模式记录输入、实例及版本、状态、结果和具体错误；恢复记录不等于恢复执行。

| 场景 | 首期行为 |
| --- | --- |
| 正常完成 | 实例最终输出通过契约校验后完成 |
| 取消排队任务 | 不再开始执行；无在途 LLM 请求时可完成取消 |
| 取消运行任务 | 收到请求后不发起后续步骤；等待当前 LLM 请求返回且传输结束后，才确认取消成功，不再将本次任务标为完成 |
| 退出桌面程序 | 中止排队与运行任务，同时停止本地与 LLM 的请求／响应传输，不采用主动取消时的等待规则 |
| 应用重启 | 内存模式清空；PostgreSQL 模式保留终态记录，未完成记录标记 APPLICATION_INTERRUPTED，不自动重跑 |
| 预算耗尽、超时、调用失败 | 返回对应的具体失败原因，不用单一通用报错，也不返回成功的空报告 |

停止本地传输不承诺远端模型供应商已停止计算或计费。取消等待期间出现超时或传输失败，优先报错，任务记为 `failed` 并保留取消请求记录；正常完成等待后记为 `cancelled`。

失败或取消后，任务保留终态和错误，实例恢复可接收任务的就绪状态，丢弃本次临时执行数据；不重启整个失败任务，不撤销已完成的外部 API 操作。退役实例仍受退役限制，不能因任务结束而重新开放调用。

错误至少包含类别、失败步骤与可读原因，按场景附带字段路径或上游错误信息；例如配置错误、输入校验失败、预算耗尽、模型请求超时、API 调用失败、模型输出校验失败。错误信息不暴露凭据。

### P07. 对外调用与去重键

以下路径均使用 `/api/v1` 前缀；完整请求与响应以运行中后端的 `/docs` 为准：

| 接口 | 语义 |
| --- | --- |
| `GET /services` | 列出稳定服务标识及其当前实例版本，首期不做权限过滤 |
| `GET /services/{serviceId}/schema` | 获取当前选定实例的输入输出契约、版本与样例 |
| `POST /runs` | 提交稳定服务标识与输入，固定当前选定实例，每次成功提交创建新任务并返回新的运行标识；首期不实现去重键 |
| `GET /runs` | 按 serviceId/status 筛选，limit/offset 分页读取历史 |
| `GET /runs/{runId}` | 查询状态、取消等待情况和具体失败原因 |
| `GET /runs/{runId}/result` | 获取通过最终契约校验的实例结果 |
| `POST /runs/{runId}/cancel` | 请求取消；请求已受理不代表已取消成功 |

**已确认：首期不实现去重键。** 每次通过校验并被接受的提交都创建新任务，不根据请求标识或输入内容复用已有任务。重复点击或请求重试可能产生重复任务及模型调用。去重机制不作为首期交付或验收要求；后续如需引入，再确定作用范围、有效期及冲突处理规则。

### P08. 运行记录与缓存

- 提供定位问题所需的阶段、通用块调用、模型调用与校验失败记录；首期不建设完整监控平台。
- 服务草稿、配置、资源源码、历史实例、任务和结果按选定仓储保存；普通环境数据不包含凭据明文。
- PostgreSQL 模式支持跨重启记录恢复及历史回退；内存模式保持会话语义。
- 日志不输出真实凭据，不默认打印整批学生答案。
- 数据保留和引用安全清理策略尚未实现；当前不自动删除历史。

### P09. 单任务预算

- 含业务包的实例配置节点级 `loop` 上限和 token 上限，并组合成任务预算；纯通用块实例不要求模型预算；API 块需绑定 API 环境并配置请求路径。具体组合规则由架构设计确定。
- 一次完整业务包调用计一轮 loop；已开始但报错的调用也计一轮，重试是新的一轮。输出契约失败可按服务 retryLimit 有界重试，预算不足时提前停止。
- 每次任务／流程状态流转前检查预算；终止与清理不能被预算检查阻塞。
- token 按供应商报告的输入与输出累计。请求前检查余额并收紧单次输出上限，响应后累计并检查；单次请求可能超额，超额时任务失败且不发布成功结果。缺失用量明确报错。
- 预算耗尽返回具体错误；显示 loop、token 使用量及供应商计量来源。

## 5. 业务包协议与实例模板

包类似可复用依赖，一个实例可组合多个包与多个配置。包仅维护 LLM 交互的输入输出结构验证、可选参数和 Prompt；数据处理由通用块节点负责，流程由实例组织。

| 包声明 | 含义 |
| --- | --- |
| packageId / version | 包标识与版本 |
| name / description | 能力说明 |
| prompt | Prompt 文件，默认 prompt.txt；平台统一执行 |
| contractRefs.input / output | 模型交互单元的严格输入输出契约引用 |
| contractRefs.configuration | 可选业务参数模型引用，不包含预算 |
| budgetDefaults | 可选节点 loop/token 初始化限额，节点配置优先 |
| 示例说明 | 输入输出及接线示例作为包内文档维护，不是清单字段 |

服务拼图声明输入、期望输出、模块节点、连接和控制结构；业务包节点包含参数、预算及模型绑定，API 通用块节点包含 API 连接引用和请求路径。平台校验并保存后形成完整实例；包契约与实例最终报告契约分别负责各自边界。

标准模板同时提供包模板、单文件通用块和服务拼图样例，说明如何组装、配置节点、保存及调用。平台统一执行模型调用、进度记录和结果校验；配置者无需手写运行入口。

当前交付目录：

```text
samples/
├── blocks/                    # minimal.py、complete.py、完整创建与配置说明
├── packages/                  # 清单/节点/环境配置、平台标准入口说明
│   ├── minimal/               # 一次模型调用
│   └── complete/              # 嵌套参数、Prompt 占位符和预算默认值
├── contracts/                 # 最小/完整独立类型与校验钩子
└── USAGE.md                   # 加载、接线、保存和调用
```

当前目录按资源分类，每类只提供最小和最完整两套可加载模板及逐字段说明；通用块的最完整示例包含 API 查询、节点路径配置和文本处理，不另设 API 示例文件；实例仍由平台编译生成，不引入手写实例执行入口。原业务算法、契约生成和流程导入脚本已移除。

## 6. 模型与流程的控制边界

模型输入输出由业务包声明的契约严格校验。模型输出可以包含契约允许的类型、枚举和业务字段；Python 通用块据此计算严格布尔条件，if/else 或 while 执行配置者预先定义的分支与循环。无效输出应在契约校验处失败。

流程、接线和实例由配置者在服务页定义，平台校验后编译生成。模型不负责生成或修改流程、脚本或实例，模型返回的数据不得直接作为可执行配置。后续扩展遵守这一边界，见 [分步计划](agent-platform-roadmap.md)。
