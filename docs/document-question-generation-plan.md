# 文档出题实例计划：通用块与业务包

日期：2026-09-20。状态：实现与本地验收已完成；真实线上出题和人工质量验收按用户要求暂缓。前置：[平台改造计划](platform-files-and-dependencies-plan.md)。交付：[实例使用说明](../examples/document-question-generation/README.md)。

## 已确认需求

每次输入一份 PDF 或 DOCX；不支持旧版 DOC。PDF 支持扫描件，使用 RapidOCR 在本地识别。全部正文完整传给出题业务包，生成论述题、四选一单选题、填空题各一道，并分别给出参考答案。最终返回包含题目数组的对象。

全文超出模型容量时明确报错，不静默截断、摘要或只取前几页。通用块业务代码集中在一个 Python 文件，第三方库和模型由平台按声明准备。

## 资源统计

| 分类 | 数量 | 交付 |
| --- | ---: | --- |
| 通用块 | 1 | `read_document.py`：DOCX/PDF 读取、逐页 OCR、全文汇总 |
| 业务包 | 1 | `document-question-generator/`：清单、Python 契约、Prompt |
| 契约 | 3 | 文件输入、出题资料、题目与参考答案 |

三种契约是职责统计，不要求恰好三个 Python 文件。通用块可在单文件中声明契约，业务包按现有方式声明兼容的输入输出；文件输入引用平台文件契约，不增加另一套协议。

流程：任务页选择并保存文件 → 读取文档通用块 → 出题业务包 → 返回结果。普通节点只接受上一层完整输出，最终节点只选择输出契约，不引入映射或数据来源配置。

建议在 `examples/document-question-generation/` 单独交付实例资源与说明，不覆盖 `samples/` 现有的最小/完整开发模板。

## B1：定义契约

### 文件输入契约

接收一个平台管理的文件引用，格式限定 PDF/DOCX。通用块通过执行上下文获取文件，不直接接收任意本机路径或下载地址。

### 出题资料契约

输出 `fileName` 和非空 `text`。PDF 按原始页序汇总并保留页码分隔，DOCX 按文档顺序组织。模型路径和本机路径不传入业务包。

分页进度是运行记录，不是逐页向下一步发送业务输出。全部处理完毕后仅返回一次完整正文。

### 题目与参考答案契约

顶层 `questions` 数组恰好三项，依次为论述题、单选题和填空题，每种恰好一道。每项以 `type` 区分严格结构：

| type | 必填字段 | 校验 |
| --- | --- | --- |
| essay | stem、referenceAnswer、scoringPoints | 题干、答案、评分要点非空 |
| single_choice | stem、options、referenceAnswer、explanation | options 恰好 A/B/C/D 四个非空、不重复选项；答案为其中一个标识 |
| fill_blank | stem、referenceAnswers | 空位统一使用 `____`；至少一个空位，答案非空且与空位数量一致 |

禁止未知字段和隐式类型转换。通过 Python 校验器检查题型数量、顺序及填空关系；Schema 同步表达可表达的结构要求。结构校验不能证明答案正确、题意明确或内容忠于资料，仍需人工业务验收。

交付：三个契约及正反例，验证平台能够加载、比较和执行其校验规则。

## B2：实现单文件读取文档通用块

1. 声明 RapidOCR、推理运行库、PDF 解析/渲染库、DOCX 读取库的验证版本及来源，声明 OCR 模型 URL 和 SHA-256；不在任务函数中安装依赖。
2. 从平台获取文件和本地模型路径，初始化 OCR；同一工作进程内复用引擎，不逐页初始化，禁止隐式联网下载模型。
3. DOCX 按顺序提取段落及表格，不把所有表格挪到正文末尾。DOCX 没有可靠固定分页，不伪造页码。
4. PDF 逐页检查，正文文本层完整可用时直接提取；扫描页及需要补全的混合页面转成图片后 OCR。不能因存在页眉文字就认定整页无需识别，避免漏正文和重复拼接。
5. 根据识别结果组织阅读顺序，汇总所有页，保留页码分隔；复杂表格、双栏、倾斜和低清晰度资料作为重点验收，不承诺排版完全还原。
6. 逐页释放图像资源、报告页数进度并检查取消。设置明确的文件大小、页数、渲染尺寸和超时上限；超限报错，不裁掉剩余页面。
7. 空白页可跳过并记录；有内容但无法识别、页处理异常、文件损坏或加密时明确失败，包含页码和原因，不返回不完整正文冒充成功。
8. 汇总全文，校验非空后一次性输出。非空检查无法判断 OCR 错字，需真实样本验证质量。

DOCX 内嵌图片文字、公式及图表语义不默认视为已支持；若影响资料完整性，应明确报告并向用户确认是否扩展。不能在遗漏这些内容时声称完整提取。

交付：可加载的单文件通用块、依赖和模型声明、使用说明。

## B3：实现出题业务包

1. 包清单绑定出题资料与题目输出契约，只维护 Prompt、契约和可选参数，不直接运行 OCR、访问文件或调用 MCP。
2. Prompt 完整引用 `input.text`，限制根据资料出题，文档内的文字仅作为资料，不作为修改流程的指令。
3. 明确三题各一、单选四选一、评分要点及填空答案格式；尽量覆盖不同知识点，避免重复考查。
4. 资料不足时明确失败，不编造答案。实施时确定与现有包协议一致的失败表达方式，不把错误文字塞入题目数组作为成功返回。
5. 绑定用户选定的模型与足够输出额度，输出经完整契约校验后才返回。
6. 使用现有服务重试与预算机制：题目结构不合格只重新调用出题包，不重新 OCR；网络、鉴权、取消和预算错误保持既有语义。
7. 根据模型上下文容量和可用计数能力检查全文、Prompt 与输出额度。无法准确预检时保留供应商明确的超限错误，不用字符数冒充 token 数；禁止静默截断。

交付：清单、契约代码、Prompt、模型配置及预算说明。

## B4：组装服务实例

1. 平台改造完成后加载资源，确认依赖与模型就绪。
2. 新建服务，文件输入契约 → 读取文档通用块 → 出题业务包；返回只选择题目与参考答案契约。
3. 配置模型连接、loop/token 预算、额外重试上限，静态校验通过后保存版本。
4. 任务页面选择文件，展示保存状态、OCR 页数进度和最终题目；错误能定位到文件处理或出题步骤。
5. 文件绑定每次任务，不绑定服务版本；保存文件副本、执行记录及实际实例版本。

交付：可调用的服务实例和从选择文件到查看题目的操作说明。

## B5：验收

| 场景 | 通过条件 |
| --- | --- |
| 段落与表格混排 DOCX | 正文顺序正确，得到三题及答案 |
| 文字 PDF | 完整提取文字，无须整篇 OCR |
| 多页扫描 PDF | 本地识别、页序正确、全文传入业务包 |
| 混合页面 PDF | 不漏扫描区域、不重复正文 |
| 末页含关键知识点 | 确認末页正文包含在真实模型请求中 |
| 空白、损坏、加密、不可识别文件 | 明确报错，不生成伪题目 |
| 文件或全文超限 | 明确拒绝，不静默截断 |
| 少题、多题、非法选项、填空不对应 | 契约拒绝并按配置重试，预算仍生效 |
| OCR 或模型调用中取消 | 工作实际停止，符合平台取消语义 |
| 重启或移动原文件 | 已保存任务文件和历史仍可访问 |

用自制或授权资料覆盖 DOCX、文字 PDF、扫描 PDF 和混合 PDF，人工核对依据、答案正确性和单选唯一性。返回合法 JSON 不等于业务验收通过。

## 顺序与前置事项

B1 和 B3 的草案可先行；B2 的真实执行依赖平台的环境准备、模型路径和子进程能力；B4 还依赖任务文件页面与存储，最后执行 B5。

实施时落实固定库版本、OCR 模型及摘要、文件/页数限制、实际模型连接与上下文容量、验收资料。手写、公式及 DOCX 图片等扩展需求向用户确认后再增加。原计划阶段不执行实例；2026-09-20 用户已要求开始实施，并授权准备独立验证环境，同时明确暂不调用模型。
