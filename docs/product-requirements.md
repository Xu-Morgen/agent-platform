# Agent Platform 产品需求文档

- 文档版本：0.2
- 日期：2026-09-16
- 状态：首期验证范围已明确，少量产品决策及技术方案待定
- 主项目：通用 Agent 服务平台
- 业务包：根目录 `samples/` 下的标准模板与文本查重包

## 1. 背景与首期目标

业务系统拥有现成 API，但新建 Agent 时仍需重复处理模型接入、工具调用、参数校验和执行状态。平台将业务能力作为服务包挂载，通过环境与服务配置形成可调用实例。

**首期至少交付两个产品：服务平台产品和业务包产品。主要目标是验证平台闭环及平台与包的方向，业务包验证可用性与严格的输入输出契约，不验证 LLM 判断的准确性。**

### 1.1 必须交付

| 产品 | 首期内容 | 验收重点 |
| --- | --- | --- |
| 服务平台 | 服务配置页、环境配置页、包加载、Python 通用流程块注册与调用、实例版本与历史回退、任务调用和结果查询 | 从挂载、配置保存到调用、结果校验的完整闭环 |
| 业务包 | 可供后续包遵循和复用的标准模板、平台接入契约与样例、可执行的简单文本查重包 | 能接入平台，输入输出严格校验，同时产出定量与定性报告 |

标准模板需包含清单、输入输出与配置契约、执行入口、平台能力调用方式及样例说明；具体组织方式在技术设计中确定。它不能只是一份目录规划。

首期查重规模为一篇约 1500 字文本与另外六篇约 1500 字文本比较。该规模是功能验收样例，不是已承诺的系统容量上限。性能优化后置。

### 1.2 首期不包含

- 权限控制与独立授权服务接入、生产级多租户治理。
- 数据库直连、数据库连接管理、本地数据库持久化、跨重启历史恢复。
- 完整 LMS 课程／作业数据采集、提交版本策略、分页一致性及学生身份关联。
- 教师复核工作流、复核结论存储、LMS 教师端页面改造。
- 复杂查重业务规则、模型准确率评估、自动给出最终抄袭判定。
- 性能优化、通用防御性框架、自动兜底、复杂重试与任务恢复机制。
- 全量 Apifox 治理、通用可视化画布、包市场、任意第三方代码沙箱。
- 多 Agent 协作、长期记忆、RAG、向量数据库、代码及扫描件查重。

严格输入输出校验、明确报错和已约定的任务终止行为仍是首期必要逻辑，不因上述收敛而省略。

## 2. 概念与责任边界

| 概念 | 定义 |
| --- | --- |
| 服务包 | 业务实现及元数据，声明版本、入口、输入输出、配置和依赖 |
| 能力契约 | 一项依赖的输入输出结构与错误约定 |
| 环境配置 | 平台管理的模型连接、API 地址、认证引用及运行参数 |
| 服务配置 | 某个包使用的环境、能力绑定与业务参数 |
| 服务实例 | 一个固定包版本与固定配置版本的组合，拥有独立实例标识 |
| 通用流程块／功能块 | 明确输入输出的确定性 Python 代码，用于固定格式处理、清洗、转换或验证 |
| 包内流程 | 组织通用能力、确定性业务计算及模型调用的业务实现 |
| 运行任务 | 一次实例调用及其固定版本、输入、状态、结果与错误 |

### 2.1 平台与包

- 平台负责配置页、环境管理、包挂载、实例版本、通用块注册与调用、模型调用、契约校验、任务状态和缓存记录。
- 包负责业务流程、Prompt、业务计算与报告结构；平台核心不包含查重算法或课程业务分支。
- 固定消息格式的解包、清洗与验证由 Python 通用块完成；例如判断哪个字段代表成绩等依赖语义的识别，由模型完成，并校验模型输出结构。
- 通用块本身是硬编码的确定性 Python 实现，不承载模型自主判断。包可将通用块与模型步骤组合使用。
- 包通过平台接口获取工具、模型、进度和结果保存能力，不硬编码环境地址与真实凭据。
- 首期只加载受信任的本地包，不要求第三方代码沙箱。

### 2.2 权限的后续方向

权限验证视为独立服务能力，后续可实现为可复用的通用包或流程，并作为服务实例通用流程的一部分接入。首个验证版本不实现权限检查，也不以拒绝未授权调用为验收条件。模型/API 的连接认证配置与业务调用者的权限验证是不同能力，前者仍在首期范围内。

## 3. 用户与主要路径

- 包开发者：依照标准模板定义契约、业务实现和样例。
- 平台配置者：配置环境，挂载包，选择能力绑定，保存服务配置，查看历史和回退。
- 业务调用方：提供文本输入，提交任务，查询状态与报告。
- 教师：阅读定量、定性报告，自行决定是否构成抄袭；首期不建设教师复核系统。

```text
环境配置页配置模型／API 连接
  → 挂载本地包并读取契约
  → 服务配置页选择环境与通用流程块、填写参数
  → 校验并保存，生成立即生效的实例
  → 提交输入并取得运行标识
  → 执行 Python 功能块及包内模型／业务步骤
  → 校验输出并返回报告，或返回具体错误
```

挂载不自动执行业务操作。无效配置不得作为可调用实例生效；“保存后立即生效”指通过校验后的成功保存，无需另行启用。

## 4. 首期平台需求

### P01. 包加载与标准接入

- 读取本地包清单、版本、契约、入口和依赖，检查必要信息及依赖是否齐备。
- 同一包可形成多个配置不同、标识独立的实例。
- 缺少依赖、配置不完整或契约无效时给出具体原因，不生成可调用实例。
- 提供可复用标准模板与接入样例，后续业务包依协议接入，不要求修改平台核心。

### P02. 服务配置页与环境配置页

| 页面 | 最小功能 |
| --- | --- |
| 环境配置页 | 配置模型连接、模型标识、凭据引用、API 连接及调用超时／预算等必要参数，供服务配置选择 |
| 服务配置页 | 挂载／选择包，依 Schema 填写参数，绑定环境与通用块，校验保存，展示生成的实例标识和版本，查看历史及发起回退 |

- 包通过 Schema 声明配置类型、必填项、默认值和说明。
- 凭据由平台环境管理，不写入业务包或日志。
- 保存校验失败时返回具体字段或依赖问题；成功保存后新实例立即可调用，不设置额外发布步骤。
- 首期不要求通用画布或任意表达式映射编辑器；固定转换通过注册的通用块选择与配置。

### P03. 实例版本与回退

- 包变更视为大版本更新；发布后的包版本不轻易修改，发生变更应发布新版本，不覆盖既有版本内容。
- 配置变更视为小版本更新；每次配置更新产生新配置版本及新实例标识，不原地修改旧实例。
- 包与配置同时更新视为破坏性的整体更新，不默认对既有调用兼容。
- 历史包／配置版本关联及实例记录保留，以支持回退。首期仅存在应用缓存内，重启后不承诺保留。
- 每次任务固定其提交时使用的实例、包及配置版本。后续更新不得改变排队或运行中任务的实际配置。
- 环境绑定应支持固定任务实际使用的连接与模型设置，避免共享环境更新间接修改旧任务；引用或快照的实现方式由技术设计确定。
- “新实例立即生效”不等于使用旧实例标识的调用自动转向新实例。旧实例是否继续接受新任务、是否提供稳定服务入口，以及回退复用旧实例还是生成新实例，见第 9 节待决策项。
- 具体版本号编码规则不预设为某种语义化版本规范，但需区分包更新、配置更新与整体更新。

### P04. API 接入与 Python 通用流程块

- 包声明能力契约，平台支持绑定 API 或已注册通用流程块组成的接入流程。
- 通用块以 Python 代码实现并明确输入输出，输入、输出均执行运行时校验；首期提供代码注册与调用能力。
- 首期必须包含固定 API 消息格式的处理能力。例如 LMS 响应：

```json
{
  "code": "10000",
  "msg": "成功",
  "subCode": null,
  "subMsg": null,
  "bizData": ""
}
```

- 对该格式由确定性通用块检查成功码、提取 `bizData` 并按目标契约校验；失败时保留 `code`、`msg`、`subCode`、`subMsg` 等可用错误信息，不转换为空的成功结果。
- 此示例不将 `bizData` 限定为字符串；其实际类型以绑定能力的契约为准。
- 例如“哪个字段是成绩列”等语义映射交给模型判断，模型返回的结构仍需校验；该例说明职责边界，不增加首期成绩识别业务包的交付要求。
- 通用块能力属于首期平台交付，即使查重包直接接收文本，也应单独通过样例验证通用块的注册、绑定、执行和校验。

### P05. 严格契约与模型环境

- 用户输入、通用块输入输出、API 响应、LLM 输出、最终报告均执行相应运行时校验。
- 契约明确字段类型、必填项、范围、枚举、嵌套结构与未知字段处理方式。
- 从单一契约来源派生类型、校验规则与公开 Schema，避免手工维护多套规则。
- 校验失败指出阶段、字段路径和原因，不通过强制类型转换、静默填值或自动兜底制造合规结果。
- 包定义 Prompt 与模型输出契约，平台管理连接、凭据、超时及预算，并提供统一模型调用接口。
- 模型输出结构校验与模型语义判断准确性是两件事。前者必须验收，后者首期不验证。
- 不建设复杂自动重试、模型降级或自动修复输出机制；发生失败明确报错。

### P06. 任务状态、取消与关闭

- 提交后立即返回运行标识，支持查询状态与结果；执行不依赖提交请求的 HTTP 连接持续存在。
- 状态至少包含 `queued`、`running`、`completed`、`failed`、`cancelled`；取消等待期间需可识别，具体采用状态还是标记由实现确定。
- 首期在应用缓存中记录输入、实例及版本、状态、结果和具体错误，不实现任务恢复。

| 场景 | 首期行为 |
| --- | --- |
| 正常完成 | 定量与定性报告均生成并通过契约校验后完成 |
| 取消排队任务 | 不再开始执行；无在途 LLM 请求时可完成取消 |
| 取消运行任务 | 收到请求后不发起后续步骤；等待当前 LLM 请求返回且传输结束后，才确认取消成功，不再将本次任务标为完成 |
| 停止／关闭应用 | 中止排队与运行任务，同时停止本地与 LLM 的请求／响应传输，不采用主动取消时的等待规则 |
| 应用重启 | 不恢复原任务；内存记录清空，原运行标识返回明确的记录不存在信息，不虚构旧任务状态 |
| 预算耗尽、超时、调用失败 | 返回对应的具体失败原因，不用单一通用报错，也不返回成功的空报告 |

停止本地传输不承诺远端模型供应商已停止计算或计费。取消等待遇到请求超时或传输失败时的最终状态优先级仍需确定，见第 9 节。

错误至少包含类别、失败步骤与可读原因，按场景附带字段路径或上游错误信息；例如配置错误、输入校验失败、预算耗尽、模型请求超时、API 调用失败、模型输出校验失败。错误信息不暴露凭据。

### P07. 对外调用与去重键

以下是建议接口语义，路径不是已实现协议：

| 接口 | 语义 |
| --- | --- |
| `GET /services` | 列出可调用实例及版本，首期不做权限过滤 |
| `GET /services/{serviceId}/schema` | 获取实例输入输出契约、版本与样例 |
| `POST /runs` | 提交实例标识与输入，每次成功提交创建新任务并返回新的运行标识；首期不实现去重键 |
| `GET /runs/{runId}` | 查询状态、取消等待情况和具体失败原因 |
| `GET /runs/{runId}/result` | 获取定量及定性报告 |
| `POST /runs/{runId}/cancel` | 请求取消；请求已受理不代表已取消成功 |

**已确认：首期不实现去重键。** 每次通过校验并被接受的提交都创建新任务，不根据请求标识或输入内容复用已有任务。重复点击或请求重试可能产生重复任务及模型调用。去重机制不作为首期交付或验收要求；后续如需引入，再确定作用范围、有效期及冲突处理规则。

### P08. 运行记录与缓存

- 提供定位问题所需的阶段、通用块调用、模型调用与校验失败记录；首期不建设完整监控平台。
- 配置、历史实例、任务、报告等运行数据当前仅保留在应用内存缓存中。包源码及标准模板仍为项目文件。
- 缓存保留支持同一应用运行期间的历史查看与回退；重启清空，不承诺跨重启留档。
- 日志不输出真实凭据，不默认打印整批学生答案。
- 流程验证通过后，随数据库能力将相关记录持久化到本地，保留周期等规则届时确定。

## 5. 服务包协议与标准模板

包声明至少包含：

| 字段 | 含义 |
| --- | --- |
| packageId / version | 包标识与包版本 |
| name / description | 能力说明 |
| runtime / entry | 运行时要求与执行入口 |
| inputSchema / outputSchema | 严格的输入输出契约 |
| configurationSchema | 实例配置字段、默认值与说明 |
| requiredCapabilities | 模型、API、通用块等必要依赖与契约 |
| examples | 有效输入输出及用于验证校验失败的无效样例 |

平台运行上下文提供通用块调用、模型调用、运行记录、进度及结果缓存接口。具体签名由技术设计确定。

标准模板须说明如何声明依赖、接收上下文、执行步骤、返回结果及报告错误。查重包按该标准接入，用于证明协议可用。

规划目录：

```text
samples/
├── template/                  # 标准模板，具体目录名可由技术设计调整
└── assignment-similarity/     # 最小文本查重包
    ├── manifest.json
    ├── contracts/
    ├── configuration/
    ├── workflow/
    ├── tools/
    ├── prompts/
    └── examples/
```

目录为组织示意，不要求创建空目录。当前尚未实现模板或业务包。

## 6. 业务包产品：最小文本查重

### 6.1 目标与输入边界

比较一份当前学生作答／文章纯文本与其余学生作答／对照文章纯文本数组，同时提供定量重复文本相似度报告与定性文本语义抄袭分析报告。

“给定文章与给定数据库”的首期边界按本次输入约定收敛为：调用方提供目标文章和从对照资料中取得的文本数组；包不负责数据库连接、检索或完整 LMS 数据采集。

建议字段名（最终以实现契约为准）：

| 输入 | 类型 | 含义 |
| --- | --- | --- |
| targetText | string | 当前学生的纯文本作答或待比较文章 |
| comparisonTexts | string[] | 其他学生作答或指定资料库提供的纯文本集合 |

不要求课程、题目、学生 ID、提交版本、快照或分页信息。对照项可通过数组索引关联报告，首期无需扩展为完整学生数据模型。

### 6.2 最小执行流程

1. 严格校验目标文本与对照文本数组。
2. 以确定性代码比较目标文本与各对照文本，生成定量重复文本相似度结果。
3. 调用模型分析目标文本与对照文本的语义关系，生成定性报告。
4. 校验模型输出与最终报告结构，返回两类报告；失败时返回具体错误。

首期无需候选召回、向量检索、题型分组、提交去重策略或复杂部分覆盖规则。

### 6.3 输出边界

- 定量报告：提供目标文本与各对照文本的数值相似度，注明计分尺度及采用的方法；具体算法、清洗规则和重复度分母在实现前确定，不让 LLM 自行编造数值。
- 定性报告：提供模型对语义相似、可能改写或潜在抄袭关系的分析理由与建议，并能关联到对照文本。
- 两类报告采用明确结构，不能仅依靠一段不受约束的自由文本作为服务返回值。
- 定量相似度不是抄袭概率；LLM 只提供建议，是否认定为抄袭由教师综合两类报告自行决定。
- 首期不输出作为最终判定的 `true/false`，不保存教师复核结论。未来可能增加 AI 的布尔结论，作为后续需求变更处理。
- 严格校验输出类型、字段和数值范围，不将 LLM 语义判断准确性作为首期验收指标。

### 6.4 功能样例

- 正常样例：一篇约 1500 字文本，与另外六篇约 1500 字文本比较，能够返回两类报告。
- 契约样例：输入字段缺失、类型错误、数组元素错误，以及模型输出缺字段／类型不符时，都应被拦截并返回具体原因。
- 定量算法以简单、可复现的样例验证实际计算行为，不能以常量或占位数字代替报告。
- 使用合成或经授权脱敏的文本。首期不设召回率、误报率、模型准确率或性能优化指标。

## 7. 后续扩展

流程确认可用后，再扩展本地数据库持久化、业务数据库连接及资料读取能力。平台状态存储与包访问业务数据库属于不同能力。

权限验证作为独立服务／通用包，后续可加入实例通用流程。性能优化、防御性机制、兜底、任务恢复、复杂查重规则与更多输入类型按实际需求逐步增加，不提前纳入最小验证版本。

## 8. 首期里程碑与验收

**首期必须完成 M1 与 M2，两类产品均需交付；平台闭环是主要验收目标。**

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| M0 需求基线 | 需求、项目说明、协作约定 | 范围一致，已确认项与待决策项分开 |
| M1 平台产品 | 两个配置页、包接入、Python 通用块、实例版本、缓存、任务调用 | 配置保存即生成可调用实例，调用后返回符合契约的结果或具体错误 |
| M2 业务包产品 | 标准模板、接入样例、最小查重包 | 按模板接入平台，完成 1 对 6 文本比较并输出定量与定性报告 |
| 后续扩展 | 数据库、权限、性能与业务规则等 | 另行确认，不作为首期阻塞项 |

首期检查清单：

- 服务配置页和环境配置页均可操作；缺失必要配置或依赖时不能保存为有效实例。
- 配置更新产生新版本和新实例，成功保存立即可调用；同一应用运行期间可查看历史并按最终选定语义回退。
- 配置更新不改变已提交任务的实际包版本、配置和模型设置。
- Python 通用块可注册、绑定和执行，固定 LMS 消息解包的成功与失败样例符合契约。
- 输入、通用块输出、模型输出及最终报告的结构错误被拦截，公开契约与运行时校验一致。
- 正常文本样例能得到真实计算的定量报告与模型生成的定性报告，不验收模型分析准确性。
- 取消请求受理与取消完成可区分；应用关闭停止本地模型传输，重启不恢复任务。
- 预算耗尽、超时和调用失败有不同、具体的报错，不以空报告伪装成功。
- 不依赖权限服务、数据库、向量服务或真实 LMS 页面即可完成首期闭环。

## 9. 剩余待决策项与技术设计

### 9.1 需要产品选择

1. 实例更新与回退：新实例生效后旧实例是否继续接受调用，是否需要稳定服务入口；回退是重新选用旧实例还是基于历史配置创建新实例。
2. 取消中的异常：等待 LLM 返回期间若超时／传输失败，最终记为失败还是取消，并如何保留具体原因。
3. 定量报告口径：选定算法、文本预处理、数值范围和重复度计算方式；输入空白文本／空对照数组是否允许，以及报告的最小必填字段。

上述未决项不扩大首期范围，但实现对应行为前需要明确，不将建议当作用户已经确认的决定。

### 9.2 技术设计事项

- 通用流程块已确定使用 Python；平台其他部分、业务包运行时及前端框架仍待选择，不据此推断整个平台只能使用 Python。
- 包和通用块的注册方式、运行上下文签名及契约库。
- 两个页面的具体布局、环境配置与实例固定版本的关联方式。
- 进程内任务执行、缓存组织、取消信号及应用关闭时的连接清理。
- 首期预算的计量方式、检查时机与超时配置；如供应商不提供用量信息，明确可执行的限制方式。
- 包与配置的版本号编码及对外接口的最终路径、错误结构。
