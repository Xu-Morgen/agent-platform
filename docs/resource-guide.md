每类资源只提供最小和最完整两套示例。推荐从无需模型或外部 API 的最小块闭环开始，再配置最小业务包。通用块的最完整示例 complete.py 包含 API 查询、响应及自定义输入校验、可选附件、进度上报、显式错误和可配置文本处理，运行前需要在节点绑定 API 连接并填写请求路径。每类示例都明确配置的作用、默认值和入口出口，不要求先理解其他业务产品。

配置与源码以当前平台实现为准：块选项通过 NodeInput.primary/references 传入，API 块另通过节点配置选择 API 连接及请求路径；包参数与模型连接通过节点配置，独立契约只描述端口。平台统一执行业务包，不提供自定义入口或生命周期 hooks。包只声明契约、参数和 Prompt；处理和转换通过通用块节点完成。

原 template、assignment-similarity、flow_templates.py 和 invoke_similarity.py 已按用户要求移除，历史交接不作为现用模板指南。后续产品体验改进见 [三类资源专项计划](resource-plan.md)。

## 更新与归档资源

通用块修改源码后必须递增 `@block(..., version='...')`；业务包更新 `package.json` 中的 version。同一标识和版本只能对应一份内容，重新加载相同内容不会重复录入，加载不同内容会明确提示版本冲突。独立契约按源码摘要区分。

首次成功导入业务包或通用块版本时，同一资源类型、同一声明 ID 的较低版本自动归档；补导入低于已导入最高版本的资源时，该资源也默认归档。版本按数字段比较，预发布低于同版本正式版。新资源与归档状态一起持久化，导入失败或版本冲突不改变旧版状态。重复导入相同资源保留当前归档状态，手动恢复的旧版不会因重复导入而再次归档。独立契约没有声明版本，仍由用户手动归档；重启不会批量归档此前已导入的资源。

服务页左侧在资源名称旁显示版本号，同一声明标识按版本从新到旧排列，并标注“最新已导入”或“旧版本”；最新指本地已导入的最高版本，包含已归档版本，不代表远端发布状态。不同声明标识分别比较，卡片显示 ID 以区分同名资源。“管理资源 · 归档 / 恢复”可归档旧版通用块、业务包和独立契约，也可恢复。归档状态持久化；归档只从添加列表和新契约选项中隐藏，已选契约仍显示，已有草稿、服务实例和任务继续引用原资源；跨执行协议升级的旧实例仅可查看历史。归档不删除源码、运行环境或历史记录，也不释放版本号。

导入新版后，在服务历史中复制当前版本为草稿，用新版资源替换相应节点，检查服务入口/出口契约与节点配置，再为原服务保存新实例版本。保存成功后新任务使用新代码；重启或重新加载资源不会自动替换已有实例。

## 节点输入协议

当前为 flow-5。资源声明 NodeInput[P, tuple[...]]，模块目录导出 primaryContract（业务主数据）及 inputContract（完整入口）。服务用户只填写业务数据。简单参考、固定参考槽位、条件与循环边界见 [USAGE](../samples/USAGE.md)。samples 的块和包均升级到 2.0.0，完整包与完整独立契约展示参考声明。旧协议实例不能复制、执行或回退激活，须通过页面重建并保存新版本。
