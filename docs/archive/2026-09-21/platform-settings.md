# 平台设置与任务并发持久化

2026-09-21 完成。用户要求：将任务并发放到平台设置中，保存落库并在重启后生效。当前说明见 [任务并发配置](../../../readme.md#任务并发配置)。

## 交付

- 新增侧栏「平台设置」与任务并发表单，范围 1～64，默认 4。分别显示当前生效值、已保存的下次启动值及重启提示；保存不调整当前消费者池，不中断任务。
- 新增严格 Pydantic 设置写入/读取契约和 `GET/PUT /api/v1/settings`。拒绝缺失字段、越界、字符串、布尔值、小数及未知字段。
- 复用平台文档存储，`settings/platform` 记录在首次启动自动保存默认配置，后续启动读取已保存值。写入成功后才更新缓存；保存失败不发布新值。无需数据库结构升级或修改服务实例版本。
- 接通 Electron 主进程固定路由、preload 与页面。重新读取可恢复已保存值；修改回当前值并保存会取消重启提示。
- 并发配置统一以数据库设置为准，移除前一阶段未提交的命令行与环境变量入口。独立 API 也读取同一设置。
- 内存开发模式页面提示无法跨重启保留并禁用编辑/保存。没有新增自动重启按钮，用户等待任务结束后自行退出重开。

## 实际验证

- 内存应用 API 验证默认值、严格输入边界、1/64 可保存、保存后当前池保持 4、改回当前值清除待重启标记、存储写入失败返回 503 且保留旧值。
- 重建应用时读取已保存值 2，实际创建两个消费者，待重启标记清除。
- 真实 Electron 页面、preload/IPC 和真实 PostgreSQL 闭环：使用独立临时目录启动，页面将 4 改为 2 后保存，当前值仍为 4、保存值为 2、显示重启提示；停止后端及数据库后重新启动，页面当前值与保存值均为 2，待重启提示消失。
- 真实持久化 API 拒绝 65；桌面和 390 像素窄窗口截图检查通过，页面无横向溢出。
- Python/JavaScript 语法与 Git 差异检查通过。

验证仅使用已有依赖及独立临时数据库，没有修改用户实际业务数据，没有调用线上模型或安装依赖。临时脚本、数据库目录及截图在完成后清理。不将该设置持久化验证表述为线上模型质量验收或并发压力测试。
