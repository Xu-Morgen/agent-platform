# Agent Platform 初版产品需求文档

- 文档版本：0.1
- 日期：2026-09-16
- 状态：已确认产品方向，待技术方案与实现细化
- 主项目：通用 Agent 服务平台
- 附属项目：根目录 `samples/` 下的 Agent 服务包

## 1. 背景与目标

业务系统拥有现成 API，但新建 Agent 时仍需重复处理模型接入、工具调用、参数校验、执行状态和部署集成。项目希望形成可复用的服务平台模板，使业务开发者将具体能力实现为服务包，在中心完成配置后即可向 LMS 等系统提供服务。

已确认的核心定义是：**包是挂载在中心下的服务，平台允许为包配置 API 或接入流程，并向包提供模型环境等通用基础能力。**

首期以简单 Agent 为边界，验证一个包从挂载到调用的完整流程。后续纳入数据库配置，但数据库能力不作为所有包的必选依赖。

### 1.1 成功标准

- 新增简单 Agent 时，开发者主要编写新包，无需修改平台核心。
- 同一包可通过不同配置接入不同业务环境。
- LMS 通过稳定的实例标识、输入输出契约和统一调用入口集成服务。
- 参数或结果不符合契约时能被拦截，错误可定位。
- 模型、API 地址及认证配置变化通过平台配置完成，不要求改写包业务代码。

### 1.2 首期不包含

- 全量 Apifox 接口治理、自动修订全部接口文档。
- 通过自然语言自动生成并上线任意 Agent。
- 通用可视化编排画布、包市场或任意第三方代码沙箱。
- 多 Agent 协作、长期记忆、RAG 和向量数据库的强制集成。
- 完整数据库连接管理及数据库访问工具。
- 自动作出学术违规处分或根据查重结果自动修改成绩。

## 2. 概念与责任边界

| 概念 | 定义 |
| --- | --- |
| 服务包 | 业务实现及元数据，声明输入输出、配置项、外部依赖和运行时要求 |
| 能力契约 | 某项依赖的用途、输入输出结构、错误约定及必要行为要求 |
| 服务配置 | API／流程／模型绑定和业务运行参数，不包含包业务源码 |
| 服务实例 | 一个包版本与一份配置版本结合形成的可调用服务，具有独立实例标识 |
| 接入流程 | 调用外部能力并进行分页、合并或转换，使结果满足包的依赖契约 |
| 包内流程 | 完成业务目标的步骤、条件路由、工具和模型调用 |
| 运行任务 | 某次实例调用的输入、固定版本、执行状态、结果和运行记录 |

### 2.1 平台与包

| 内容 | 平台负责 | 包负责 |
| --- | --- | --- |
| 服务管理 | 路径加载、注册、实例配置、启用和停用 | 名称、描述、版本和入口 |
| 类型约束 | 加载契约、运行时校验、公开 Schema | 定义输入输出和业务校验 |
| API 接入 | 连接地址、认证、映射、超时、运行记录 | 声明所需能力，提供必要适配逻辑 |
| 流程接入 | 注册与调用流程，检查绑定契约 | 声明依赖契约和业务流程 |
| 模型环境 | 模型连接、凭据、调用预算和统一调用接口 | Prompt、输出契约、模型能力要求 |
| 运行管理 | 调度、状态保存、取消、错误与运行记录 | 节点执行逻辑和业务错误 |
| 配置管理 | 根据 Schema 提供配置入口，验证和保存版本 | 配置 Schema、默认值与说明 |
| 业务结果 | 提供通用结果和文件存储接口 | 结果结构、证据内容和业务说明 |

### 2.2 工具分类

- 数据工具：读取 API、文件或检索结果，不应产生预期外的业务写入。
- 实施工具：执行写入或外部动作，声明副作用和重试限制。
- 逻辑工具：执行确定性计算、过滤、转换和汇总。

工具按实际行为分类，不能仅依赖 HTTP 方法判断。平台内部工具调用不要求都由 LLM 发起，确定性流程可以直接调用。

## 3. 用户角色与主要路径

- 包开发者：定义契约和业务实现，提供配置说明与样例。
- 平台配置者：挂载包，绑定 API／流程／模型环境，验证配置并启用实例。
- 业务调用方：根据实例契约发起调用，查询任务并获取结果。
- 业务复核者：在需要复核的场景中查看证据，记录业务结论。

主要路径：

```text
提供包路径
  → 平台读取清单与依赖声明
  → 创建服务实例草稿
  → 展示并填写配置
  → 绑定 API／接入流程／模型环境
  → 校验配置与契约
  → 执行受控连接样例
  → 启用实例
  → 业务系统调用
  → 返回结果或可定位的失败信息
```

挂载不得自动执行包的业务操作。首期只加载受信任的本地包；包加载与执行的技术边界在实现阶段确定。

## 4. 首期平台需求

### P01. 包加载与实例注册

- 配置一个或多个包路径，读取清单、版本、契约和运行时要求。
- 检查清单有效性、包版本兼容性、依赖是否可用及实例标识冲突。
- 支持同一包创建多个独立实例，各实例绑定自己的配置。
- 缺失依赖或配置不完整时保留草稿并给出原因，不暴露为可调用实例。
- 停用实例后拒绝新的调用；首期允许已启动任务继续按原配置执行，也可显式取消任务。

### P02. 配置入口

- 包通过配置 Schema 声明字段类型、必填项、默认值和说明。
- 平台提供配置页面，至少支持基本表单、连接选择和字段映射。
- 配置保存与启用分开。凭据仅保存或引用在平台环境中，不写入包。
- 配置变化生成新版本，运行任务记录其启动时使用的版本。

### P03. API 与流程绑定

- 包声明某项能力的输入输出契约，平台允许将其绑定到 API 或已注册接入流程。
- API 绑定支持请求参数来源、认证引用、响应字段映射和业务错误判断。
- 简单映射由平台完成；分页、跨接口关联及复杂转换由接入流程完成。
- 首期接入流程可通过代码注册，无需可视化画布。
- 连接测试同时检查网络、认证和样例结果契约。一次调用成功不代表所有业务场景均已验证。
- 实施工具的测试使用明确的测试环境与样例，不能自动向生产业务执行探测性写入。
- 后续可将依赖绑定为其他已挂载服务；跨服务版本、循环依赖和执行预算需另行设计。

### P04. 契约与运行时校验

- 用户输入、工具参数、外部响应、LLM 输出和最终结果均经过相应契约校验。
- 契约应表达必填字段、范围、枚举、嵌套结构和未知字段处理方式。
- 使用单一契约来源派生类型、校验规则和公开 Schema；具体技术方案待定。
- 结构校验通过不代表业务内容正确；包另行验证对象存在性、范围、证据引用等业务约束。
- 校验失败返回具体阶段和字段信息，不能通过强制类型转换或静默填造数据继续执行。

### P05. 模型环境

- 平台统一管理模型连接与凭据，包通过上下文获取模型能力。
- 包声明必要能力，例如文本、视觉、结构化输出或工具调用；启用时检查环境是否满足。
- Prompt、变量定义和输出契约属于包。模型连接、调用预算和凭据属于实例环境。
- 记录模型配置标识、模型版本信息（如可得）、耗时、用量和错误，不记录明文凭据。
- 提供有限重试及失败反馈，避免无界模型循环。结构化结果仍需本地运行时校验。
- RAG、记忆和向量存储按可选依赖扩展，简单 Agent 可不使用。

### P06. 任务执行与状态

- 支持提交任务并立即取得运行标识，业务方按标识查询状态及结果。
- 首期状态包含 queued、running、completed、failed、cancelled；部分覆盖由结果的完整性字段描述。
- 包按需报告阶段和进度。长任务不能只依赖一次 HTTP 连接维持运行。
- 持久化输入引用、包版本、配置版本、状态、错误和结果引用。
- 工具根据实际副作用定义重试策略，不能对所有失败统一盲目重试。
- 首期不承诺从任意节点精确恢复；恢复能力启用前必须定义检查点和外部写入的幂等策略。
- 需要交互式 Agent 时，后续增加等待输入、恢复和检查点能力；首个查重包生成报告后即可完成，教师复核独立于任务状态。

### P07. 对外接口与类型发现

以下为建议接口语义，路径不是已实现协议：

| 接口 | 语义 |
| --- | --- |
| `GET /services` | 当前调用者可访问的已启用服务实例 |
| `GET /services/{serviceId}/schema` | 实例的输入输出契约、版本和示例 |
| `POST /runs` | 提交 serviceId、input 及可选去重键，返回 runId |
| `GET /runs/{runId}` | 查询状态、进度和失败原因 |
| `GET /runs/{runId}/result` | 获取结果及证据引用 |
| `POST /runs/{runId}/cancel` | 请求取消任务 |

运行时服务目录与编译期枚举分开。平台可根据固定目录版本生成 TypeScript 标识和类型映射；新增服务不会自动改变已经编译的 LMS 客户端。动态调用始终通过运行时契约校验。

### P08. 调用上下文与可观测性

- 业务身份、租户和授权范围由平台或可信的业务服务传入，不能交由 LLM 任意生成。
- 服务目录、任务、结果和证据访问遵循调用者权限，实例配置与运行上下文隔离。
- 保存节点状态、工具选择、校验失败、模型调用及结果引用，提供定位问题的运行记录。
- 每个包提供必要的输入输出样例；平台支持执行样例并检查契约。
- 日志区分元数据与业务内容，按需要保存证据，不默认打印整批学生答案和访问令牌。

## 5. 服务包协议草案

包声明至少包含：

| 字段 | 含义 |
| --- | --- |
| packageId / version | 稳定包标识及版本 |
| name / description | 面向配置者的能力说明 |
| runtime / entry | 运行时要求与执行入口 |
| inputSchema / outputSchema | 服务公开契约 |
| configurationSchema | 实例配置项定义 |
| requiredCapabilities | API、流程、模型等依赖及契约 |
| examples | 可用于理解和受控验证的样例 |

平台提供的运行上下文至少包含工具调用、模型调用、运行记录、进度更新、结果／证据保存能力。具体方法签名由技术设计确定。

规划的包目录：

```text
samples/<package-name>/
├── manifest.json
├── contracts/
├── configuration/
├── workflow/
├── tools/
├── prompts/
└── examples/
```

此目录为产品概念示意，不强制每个包创建空子目录。依赖锁定、执行产物与测试目录在运行时方案确定后补充。包不携带真实环境凭据和生产数据。

## 6. 附属示例：LMS 作业查重服务

### 6.1 目标与边界

在指定课程和作业中，读取已提交学生的答案，结合题型和内容生成疑似相似关系、关联学生 ID 与可核验证据，供教师判断是否存在抄袭行为。

首期支持同一题目或可比较题目版本下的开放式文本答案。选择、判断、固定填空等不直接以答案相同判定疑似抄袭。代码、扫描附件和复杂公式作为后续策略扩展。

分析范围只覆盖本次取得的提交，不能据此宣称已检查全网、历史课程或所有外部来源。相似关系不自动确定抄袭方向。

### 6.2 包依赖及平台配置

包标识建议为 `lms.assignment-similarity`，目录为 `samples/assignment-similarity/`。

| 依赖 | 包的要求 | 平台配置方式 |
| --- | --- | --- |
| 获取作业提交数据 | 按课程和作业读取题目及全部目标提交 | 绑定 LMS API，或绑定分页查询与合并流程 |
| 结构化文本模型 | 根据候选片段与题目背景分析证据 | 选择模型配置与预算 |
| 证据存储 | 保存原文片段、定位信息与报告 | 使用平台基础存储能力 |

平台接入流程负责外部数据获取和转换；包内流程负责分组、候选比较、证据分析与学生关联。

### 6.3 输入与数据契约

建议公开输入为 courseId、assignmentId，可选 questionIds、submissionPolicy 和 analysisProfile。租户和调用者身份来自可信上下文。

获取数据能力至少返回：

- 题目 ID、版本、题型和题干。
- 学生 ID、提交 ID、提交版本、提交时间和答案内容。
- 数据快照标识，或可用于记录本次读取版本的等价信息。
- 分页完成情况及预期／实际提交数量（如接口可提供）。

参考答案、教师模板、协作规则和附件解析信息作为可选背景。缺失背景或无法保证读取一致性时，在结果中明确记录限制；不能默认为完整数据。

### 6.4 执行流程

1. 校验输入、调用权限及配置，读取题目和提交数据。
2. 固定本次输入快照，按提交策略处理重复提交，检查分页完整性。
3. 按题目版本和题型分组，排除空答案或不支持项并记录原因。
4. 清洗格式并保留原文位置映射，识别题干、公共模板和明确引用。
5. 使用确定性比较筛选候选答案对，必要时扩展语义检索。
6. 计算匹配片段等证据，再由 LLM 分析候选的特殊相似与合理解释。
7. 程序校验模型引用是否真实存在，关联可信的学生及提交 ID。
8. 汇总报告、覆盖情况和失败项，返回 LMS 展示并供教师复核。

学生答案是待分析数据，其中包含的指令不构成系统指令。学生身份关联由程序完成，模型无需生成学生 ID。

### 6.5 结果要求

- 每个学生的分析覆盖状态与发现类型分开记录。
- 发现类型至少包含未发现显著匹配、需要复核、证据不足和策略不适用。
- 关联学生列表包含题目、双方提交版本、证据引用和关系说明。
- 证据包含双方原文片段、定位信息、排除的共同来源和分析方法。
- 最终报告包含输入快照、实际分析数量、跳过项、失败项、包与配置版本。
- 任务完成不等于教师复核完成，自动分析结果与最终业务结论分开保存。
- 检索分数或文本相似度不得标成抄袭概率；缺乏校准的数据不能包装为统计置信度。
- A 与 B 相似、B 与 C 相似，不意味着 A 与 C 已被证实相似；关联图保留逐对证据。

### 6.6 样例与评估

优先使用合成或经授权的脱敏样例，覆盖独立答案、整段复制、改写、公共模板、引用、短答案、缺失背景、分页不全和模型引用错误。

分别评价候选召回、误报、证据定位准确性、结构化输出通过率、耗时和调用成本。涉及业务质量的阈值需通过样例与教师复核确定，当前不设未经验证的准确率承诺。

## 7. 后续数据库配置

后续区分两类数据库能力：

1. 平台内部存储：保存配置、实例、任务状态和运行记录，由平台部署管理。
2. 包的业务数据库依赖：由包声明能力契约，平台配置连接、权限、Schema 范围和绑定实现。

业务数据库连接应采用平台配置与引用方式，不能随包分发真实凭据。后续需设计连接测试、查询／写入权限、结果契约和操作记录。向量数据库属于可选存储适配，不等于完整知识库。

首期允许为平台状态选择一种固定持久化方案，无需先实现通用数据库配置界面。

## 8. 里程碑与验收

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| M0 需求基线 | readme、协作约定、产品需求 | 主项目与样例包边界一致，待定项明确 |
| M1 最小服务模板 | 包加载、契约、配置、API／流程绑定、模型环境和调用入口 | 一个最小包完成配置后可调用，缺少依赖不能启用 |
| M2 查重示例 | 文本答案读取、候选分析、证据结果和任务状态 | LMS 可发起任务、获取关联学生及证据，失败与未发现明确区分 |
| M3 复用验证 | 第二个简单能力包或同包第二环境实例 | 无需修改平台核心即可接入，配置与任务互不串用 |
| 后续扩展 | 数据库配置、RAG、恢复能力及更多题型 | 按具体需求另行确定范围与验收 |

首期平台验收还应覆盖：

- 绑定结果不符合依赖契约时拒绝继续执行并给出具体错误。
- 配置或模型环境变更不影响已启动任务的版本记录。
- 对无权限的实例、任务和证据访问予以拒绝。
- 简单 Agent 无需业务数据库或向量服务即可运行。
- 导出的公开契约与实际执行校验一致。

## 9. 待定技术问题

- 首期选择 Python 还是 TypeScript，以及对应框架和契约库。
- 平台管理界面的技术方案、源码目录和部署形态。
- 包运行在共享进程、Worker 还是独立进程；首期仅承诺受信任包。
- 状态持久化、任务队列、证据文件存储及数据保留周期。
- 配置界面的最小交互、接入流程注册方式和 SDK 生成方式。
