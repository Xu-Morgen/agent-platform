# V1 产品细化与扩展计划

当前最小产品已由用户确认验证完成。2026-09-17 起保留现有闭环：加载资源 → 配置环境/拼图 → 保存实例 → 调用/查看结果 → 版本回退。2026-09-18 新需求优先推进 [Agent 定位与分步实施](agent-platform-roadmap.md)：R3 的桌面本地数据库、持久化与凭据恢复已通过真实集成检查，备份和清理策略仍待完成；模型严格契约与脚本控制分支为明确边界。以下保留其他后续事项，不表示全部实现。

## 目标与非目标

当前优先完成跨重启记录，并保持模型契约和脚本控制流程的边界；其余配置体验、版本解释及任务规模按下表推进。三类资源单独按 [专项计划](resource-plan.md)推进。

首阶段不扩大为插件市场、无限画布、多 Agent 平台或自动生成任意代码的系统；保持 Python 受信任本地资源、明确契约和人工保存实例。

## 交付顺序

| 阶段 | 用户问题与改进 | 可交付范围 | 验收条件 |
| --- | --- | --- | --- |
| R1 配置可理解 | 初次使用需要反复查看源码和 JSON | 资源搜索/分类、契约预览、嵌套参数表单、错误定位、未保存提示 | 从模板完成纯块服务及双包服务；错误能定位到节点和字段；刷新前提示未保存内容 |
| R2 版本可管理 | 看不出一次更新改变了什么，资源反复加载难管理 | 实例差异、资源引用关系、配置导入导出设计、未引用资源清理 | 明确模块/配置/环境的变化；导入重新绑定环境且不携带明文凭据；不破坏在途任务或历史 |
| R3 使用可持续 | 重启丢失配置与任务，记录持续增长 | 仓储接口、PostgreSQL 持久化、凭据存储方案、保留/清理策略 | 重启恢复配置历史；中断任务标记明确；版本切换原子；清理不得删除被引用快照 |
| R4 运行可扩展 | 串行队列等待长或重块阻塞页面 | 队列上限、等待/耗时展示、背压、受控并发或进程隔离 | 能测量等待和执行时间；超载明确拒绝；取消/预算/环境占用语义在并发下保持一致 |

R0 清理与模板交付已完成，记录见 [历史归档](archive/README.md)。R1 不依赖持久化，可先交付。R2 导入导出须先定义可携带的源码快照和依赖格式，不能只导出进程内 resourceId。R3 完成前不启用多个 API/worker 进程共享任务。R4 先测量，再选择进程或服务拆分。

### R1 本轮交付：服务流程编辑器（2026-09-18）

- 服务页改为结构化纵向流程图，显示开始、节点、分支汇合、循环体与结束。模块库支持分类搜索，路径首尾及节点之间可用「＋」插入，节点支持同一路径内移动和删除。
- 数据映射按「来源 → 目标」显示，来源包含服务输入、作用域内前序节点输出、循环携带值及固定 JSON 值；字段展示类型、必填状态与契约说明。节点配置按需展开，校验问题可定位到节点。
- 保留现有 FlowDraft、后端契约校验和版本保存语义。此次没有引入自由拖线或无限画布；R1 中嵌套参数表单及离开页面未保存提示仍待交付。
- 轻量验证：使用现有 Electron 与独立内存后端检查搜索、定点插入、节点移动后的失效引用、分支/循环嵌套、草稿保存、模型配置弹窗，以及 960/600 像素窗口布局。两节点文本流程通过真实校验、实例保存和任务执行，输入 `"  hello  "` 返回 `"hello"`；未调用外部模型。

### 配置页面视觉统一（2026-09-18）

- 环境页采用连接列表与配置详情布局，分组展示地址、凭据、超时和模型验证；列表可添加、切换、移除连接，凭据可临时显示，切换连接后恢复隐藏。
- 服务页将当前服务选择移到流程上方，展示节点数量，统一草稿和版本保存的操作区；版本历史以卡片区分当前版本，支持查看快照、复制草稿及回退。
- 已使用现有 Electron 和独立内存后端验证环境保存、凭据引用保留、连接切换、版本保存/复制/回退，以及原流程编辑与真实纯块执行。两页在 960/600 像素窗口下无横向溢出。未新增依赖或调用外部模型；本轮不包含环境占用规则或模型诊断协议变更。

## 可扩展点

- 新业务：通过块、包和配方交付，平台不增加具体课程或业务算法分支。
- 模型接入：当前统一使用 OpenAI 兼容协议；确有新的协议需求时再扩展，保留输出限额、用量记录与取消行为。
- 外部 API：通过独立通用块组织接入，现已支持环境连接选择和节点请求路径配置；后续增加输入输出契约反馈；业务包不再声明 API 能力；未来业务数据库访问与平台内部持久化分开设计。
- 契约体系：补资源引用和兼容性报告，优先利用现有 Schema 与运行时校验，不维护第二套手工模型。
- 任务展示：持续呈现排队、节点、循环路径、实际用量与终态；先改善查询体验，确有刷新压力再引入推送。
- 原查重产品已按模板重建要求从 samples 移除，其历史业务需求不作为当前模板工作项；后续重新开展须明确业务交付范围。

## 可优化点与测量

当前优化候选来自代码结构，不代表已测得性能瓶颈：任务状态复制/写回、目录类型解析、流程节点查找、内容快照重复引用、前端整页渲染。先记录队列等待、节点耗时、最大输入大小、会话资源和任务内存增长，确认主要成本后再优化。

在 R3 中制定最大保留记录和快照回收策略；在 R4 中确定任务上限和可接受响应时间，具体阈值由实际业务负载确定，本轮不虚构容量承诺。提示错误、类型契约、用量真实性、取消与固定快照始终保留。

## 实施约定

按分步计划选择可独立验收的交付事项，写明改动、局部验证和未完成边界。新需求必须更新当前需求与指导样例。用户本次“验证完毕”作为产品基线确认；本轮不重新调用付费模型，也不把本地协议检查写成新的真实模型验收。
