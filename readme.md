# Agent Platform

面向业务系统的通用 Agent 服务平台。将 Agent 包挂载到中心，在平台上配置 API、流程和模型环境，形成可被业务系统调用的服务实例。

本仓库以**服务平台**为主项目。Agent 包是遵循平台协议的附属项目，统一放在根目录 `samples/` 下；首个规划示例为 LMS 作业查重服务。

## 核心概念

| 概念 | 定义 |
| --- | --- |
| 服务包 | 业务实现及契约，声明输入输出、所需能力和配置项 |
| 服务配置 | 当前环境中的 API、流程、模型绑定及运行参数 |
| 服务实例 | 一个固定包版本与一份固定配置版本组合成的可调用服务 |
| 服务平台／中心 | 负责包挂载、配置、校验、运行和对外调用，并提供共享基础环境 |

```text
服务包声明依赖
    → 平台配置 API／流程／模型绑定
    → 校验并启用服务实例
    → LMS 等业务系统通过统一接口调用
```

同一服务包可以在多个业务环境中复用。包面向能力契约编写；具体接口地址、认证方式、字段映射和模型凭据由平台管理。必要时，一个依赖可以绑定为调用多个 API 的接入流程。

## 平台与包的边界

- 平台提供通用的配置管理、契约校验、工具执行、模型调用、任务状态和运行记录。
- 包定义业务工具、业务流程、Prompt、结果结构及必要的环境能力。
- 平台接入流程负责将外部数据转换为包需要的契约；包内部流程负责处理业务。
- 工具分为数据工具、实施工具和逻辑工具；输入输出均需要运行时校验，编译期类型不能替代校验。
- 后续扩展数据库连接配置与能力绑定；平台运行状态存储和包访问业务数据库是两个独立概念。

## 首期范围

完成一个简单 Agent 服务的完整挂载链路：加载包、展示配置项、绑定 API 或流程、选择模型环境、验证配置、启用实例、发起调用并返回符合契约的结果。

LMS 作业查重用于验证平台协议：读取同一课程、同一作业中已提交学生的答案，结合题型和内容生成疑似相似关系、关联学生 ID 和可核验的证据，供教师复核。业务判断留在示例包中。

数据库配置、RAG、向量存储、可视化编排和多 Agent 协作属于后续扩展，不作为简单 Agent 首期运行的必选依赖。
