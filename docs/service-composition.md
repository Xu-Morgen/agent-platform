# 固定版本服务组合与契约选择

更新日期：2026-09-21。

## 将服务加入拼图

1. 先通过服务页保存一个可独立调用的服务。
2. 新建或打开父服务草稿，在左侧「服务」Tab 或流程「＋」弹窗中搜索并添加该服务。
3. 展开服务节点，检查固定实例标识、版本及输入输出契约。需要其他版本时，在节点中明确选择历史版本。
4. 选择父服务的输入输出契约，完成接线与预算配置，校验并保存父实例。

服务节点接收上一层完整业务数据，返回子服务最后一步的完整业务输出。它不开放外层 references；内部节点仍按子服务原流程封装 NodeInput。子服务第一步的 primary 是本次服务节点的业务输入，不能读取父流程其他节点或另一轮的残留数据。结构转换仍由明确的通用块完成。

首版支持一层嵌套：子实例不能再包含服务节点，服务也不能引用自身历史实例。可以在同一父流程中多次使用同一个子实例，也可以把服务节点放进父流程的 if/repeat/while 中。三类资源保持不变，服务是已保存实例的组合入口，不是第四种本地资源文件。

## 固定版本与运行规则

- 服务节点保存 `serviceId` 与 `instanceId`，父快照保留固定子快照并将其内容摘要计入父实例身份。子服务升级或回退不会改变父实例；升级引用需要编辑父草稿并保存新版本。
- 持久化通过不可变实例记录、资源源码字节及依赖锁恢复整个引用关系，先恢复叶子再恢复父实例，不依赖源路径或数据库返回顺序。被引用子实例属于父快照依赖，后续清理策略必须保留这些引用。
- 退役实例仍不能直接接受新调用；父实例执行自己的固定子快照不经过子服务稳定入口，也不创建第二个任务。
- 内部节点继承原参数、模型/API 连接、节点预算及 retryLimit。环境在父任务提交时统一固定并占用，取消和应用退出统一作用于整个任务。
- 每次实际模型尝试同时计入内部节点、所属服务节点和父任务预算。子服务任务预算在父任务内按该服务节点累计；同一个服务节点被循环调用时不会重置预算。不同服务节点的预算分别累计，父任务总预算共享。
- 内部错误沿用子实例的节点重试；子服务本身不整体重试。子服务末尾为普通包/块时，父流程直接下游的主输入校验失败归因于该内部生产者，仅重试它。参考或跨字段校验失败不重试；末尾是控制容器时，跨服务边界失败明确终止，不重放分支或循环。
- 步骤与包用量使用 `服务节点/内部节点` 区分同名节点；任务历史从固定子快照解析资源名称。历史快照包含子流程内容。

此能力是 flow-5 的新增节点类型，未改写已有 flow-5 实例；更早协议仍只读。任务断点续跑与多 Agent 明确不考虑；固定服务组合不引入自主 Agent 协作。当前也没有多层服务嵌套、动态服务路由或自动升级引用。

## 资源与契约选择

- 资源栏提供「全部、包、块、契约、服务、控制」Tab，支持名称、用途搜索；服务列表另支持名称和标识搜索。服务资源每个服务显示一个可复用版本，历史版本在节点中切换。
- 包和块按同类型、同声明 ID 仅展示最新已导入版本，旧版本不出现在资源管理、添加步骤、条件块候选或契约来源中。恢复旧版归档状态也不会使其显示；最新版已归档时不回显旧版。已有流程的固定引用保留，不自动升级或改写。
- 服务输入、最终输出、分支输出和循环携带契约使用统一内容选择器。可按字段、类型或来源搜索，并按包、块、独立契约来源筛选。
- 契约卡片首先直接展示来源资源名称、类别、版本和主数据输入/输出用途，有资源说明时同步展示。同一资源的输入输出来源合并为一条，不必展开即可辨认；字段与类型放在其后的数据结构区。
- 数据结构区的字段名与必填标记在首行，类型与枚举值独占下一行，说明另起一行；资源栏、契约弹窗和节点详情共用此布局，避免窄卡片中类型逐字换行。结构标题不再重复罗列字段，完整约束仍可展开查看。
- 块与包在资源卡片、插入选择卡片及流程节点的常显区域展示参考数量、从零开始的位置 `references[index]`、类型和作用。数量与顺序来自入口 Schema；作用来自对应位置的 description，入口整体说明与引用类型的结构说明分别展示。未声明位置用途时明确提示，不推测业务作用；零参考直接显示无需参考。
- 结构及可比较校验规则相同的契约合并为一个共享身份，展示字段、必填性、完整 Schema 与全部来源。规范化会忽略展示标题、说明等差异，但保留默认值、类型约束及校验配置，比较别名和隐藏的 Pydantic 配置。
- 自定义 Python 校验、其他不可比较规则或缺少校验描述的历史块不自动合并。JSON Schema 相同并不代表任意 Python 校验逻辑等价。
- 明确选择共享契约后，新草稿使用共享标识；已有草稿、资源声明和历史快照的原引用继续有效，不被静默替换。资源归档只影响新选择项，既有引用仍保留。

新增只读接口为 `GET /api/v1/service-components` 和 `GET /api/v1/contracts`；请求/响应权威定义分别在 `contracts/services.py` 和 `contracts/catalog.py`。拼图节点权威定义为 `contracts/flows.py` 中的 `ServiceNode`。

## 验证范围

服务组合交付时通过实际 Electron 与独立内存后端完成资源加载、契约选择、叶子与父服务保存、真实纯块嵌套执行、历史节点名称和 960/600 像素布局检查。离线模型适配器用于验证重试、预算、环境占用和取消，不代表真实模型验收。

恢复验证使用经过 JSON 序列化的仓储记录与源码快照，检查乱序实例恢复和源文件删除后的运行；该轮没有重新进行 PostgreSQL 桌面重启生命周期验收，也没有调用外部模型。具体记录见[历史实施记录](archive/2026-09-20/fixed-service-composition-plan.md)。
