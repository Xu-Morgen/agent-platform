## 1. 执行方式

以快速交付为目标，每次开发迭代只领取一张任务卡，交付一个主要结果。I1—I5 是组织任务的阶段，不是要求一次完成的大任务。每张卡包含目标、前置任务、输入依据、交付物、范围、最小验收、验证方式、完成证据和交接记录。

同一功能必要的接口适配、错误处理和轻量验证与实现一并完成；不把两个独立功能合并，也不把每个函数拆成单独任务。完成卡片后回填记录，后续任务按依赖继续；不自动提交 commit 或发布。

技术栈为 FastAPI + Pydantic + LangGraph + PostgreSQL，桌面使用 Electron。PostgreSQL 在后续数据库版本启用，当前仍仅内存。I1 已有可执行代码与验收记录；未完成任务中的目录、端点和文件仍是目标交付物。

所有卡片共享本节规则，无需复制需求或架构原文。任务卡描述的是实现范围，不能覆盖产品规则；发现真实冲突先指出，技术细节可在既定技术栈和范围内自行决定并记录。

## 2. 领取、完成与交接

### 2.1 领取条件

1. 阅读 [AGENT.md](../AGENT.md)、任务卡引用的需求与架构章节，以及前置任务的实际实现。
2. 检查 Git 工作区，保留已有修改；确认依赖状态及已有授权，不能把“有文件”当作“已完成”。
3. 选择依赖均已完成的一张卡，标记进行中。可在阶段内按依赖调整顺序，不并行修改同一交付物。
4. 尚需下载或安装依赖时，按已有协作约定取得授权；该限制不阻止只读检查和已授权文档工作，不重复询问已有授权。

### 2.2 统一完成条件

- 本卡单一目标真实可用，交付物位于合适模块，满足引用的契约和最小验收。
- 最小验收已执行并记录结果；没有执行的检查写明未执行，不写“应当通过”充当证据。
- 不以空函数、常量成功报告或未接线界面标记完成。卡片明确允许的合成模型、策略注入点只证明该阶段能力，不代表完整平台交付。
- 没有顺带实现下一卡、引入数据库持久化、自动重试、复杂测试平台或新技术栈。
- 回填本卡交接记录，并更新本页任务索引状态。仅当本卡所有要求满足时才标记完成。

### 2.3 状态与交接格式

状态使用：未开始、进行中、阻塞、完成。依赖未完成时保持未开始；执行中遇到缺少必需外部条件则标记阻塞，明确条件，不虚构结果。

每张卡末尾的交接记录在实施后替换为：

```text
状态：完成／进行中／阻塞
实际文件：真实路径及重要入口
验证：实际命令或手动步骤 → 关键结果
使用环境：本地替身／真实模型；必要的非敏感版本信息
未完成与阻塞：没有则写无，否则写具体缺口
实现决定：需要下游知道的协议字段、默认值或边界
下一可执行任务：任务 ID 及依赖是否满足
```

代码尚未存在时不预设不可执行的验证命令；实现者须回填能直接复现的实际命令。公共接口首次实现时，提交模型及最小请求/响应样例；下游引用已有来源，避免重复定义类型。

## 3. 轻量验证策略

首期以局部可运行、尽快完成闭环为目标，不设覆盖率门槛，不搭建大型自动化平台，不默认运行全量测试、浏览器矩阵、压力测试、打包或发布。

| 交付类型 | 最小验证方式 | 证据 |
| --- | --- | --- |
| 文档 | 链接、依赖和差异检查 | 检查结果 |
| 工程入口、页面 | 一次本地启动或手动操作 | 步骤、响应或必要截图 |
| API、包、通用块 | 一个正常样例及本卡指定错误样例 | 请求和脱敏结果 |
| 契约、版本、计分、预算 | 少量纯函数/局部断言，优先复用既有样例 | 实际断言命令与结果 |
| 取消、环境占用、进程退出 | 可控本地服务或事件屏障，按卡片触发指定场景 | 终态、调用计数、连接或进程释放结果 |
| 真实查重 | 一次真实模型的 1 对 6 样例 | 脱敏两类报告、模式和用量 |

一张卡只验证受影响行为，不重复全量回归。竞态场景用显式暂停/放行事件控制顺序，避免长时间 sleep 或随机反复运行。每次接入新边界再补相应验证，轻量不意味着省略已确认的错误语义。

可复用一个小型本地响应服务，逐步增加成功、延迟、断连及 usage 样例；不单独建设模拟平台。测试替身不得进入真实业务结果冒充模型输出。

依赖以任务卡明确列出的 ID 为准；按阶段从索引中选择依赖已满足的卡；编号不是严格执行顺序，例如服务配置页面须先完成 I2-T12 加载接口。I5 的纯契约或计分卡可在依赖满足后提前做，但不能提前宣布业务产品完成。

提前引入的是后续接入点而非虚假实现：I3 的统一状态检查入口先支持契约校验和注入策略，I4 再实现并装配取消及预算策略；I1 空闲退出与 I4 在途退出分别验收。I2 回退验证使用固定快照，真正的排队/运行任务隔离在 I3 和 I4 平台演示中验证。

## 8. 首期完成与后续边界

M1 必须有可操作桌面配置、完整版本回退、稳定调用、严格契约、明确错误、任务终止及预算；I4-T12 的替身演示验证平台控制能力。M2 必须有可复用包/实例模板和真实模型查重结果；I5-T08 缺少端点或凭据时记录阻塞，不以模拟结果宣称完成。

PostgreSQL 的表结构、迁移、事务保存、跨重启历史回退属于后续数据库迭代，届时按同样规则拆卡，当前不提前创建数据库开发任务。恢复未完成任务与 LangGraph checkpointer 另行定义。权限、性能优化、复杂重试、沙箱、多 Agent、可视化画布不属于首期范围。
