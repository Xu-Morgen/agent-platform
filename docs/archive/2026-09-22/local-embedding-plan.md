# 本地 embedding 模型与平台语义搜索实施计划

创建日期：2026-09-22。开发分支：`embedding`。

状态：P1～P6 已完成并归档；已按后续用户授权下载制品并安装依赖、完成轻量性能测量；少量合成资料的语义/词面对照、真实页面与 PostgreSQL 生命周期验收已完成，结果和限制见本目录验收记录。当前操作入口为 [使用手册](../../local-embedding.md)。下文保留原始规划阶段的范围与授权约束，后续授权和实际完成情况见各阶段实施记录。

## 需求与目标

用户要求在平台设置中导入本地 embedding 模型或选择已经导入的模型，由平台提供语义搜索接口。结合本轮讨论，首版采用本地 CPU 推理，对单次任务固定的文档片段生成向量，在任务内存中检索与复用，结束后清理。

目标是补充现有词面检索对同义表达的召回能力，同时保留平台、普通块与 Prompt 包的职责。语义检索效果须用实际样例比较，不能预先认定一定比词面检索准确。

本轮仅编写计划，不修改正式服务、不触发既有 ds 调用授权、不安装依赖、不建设向量数据库。

## 当前基础与范围

- 默认 RAG 路径为列举文档、读取 DOCX、词面检索、整理登记证据；读取范围受服务输入限制。参见 [知识库说明](../../knowledge.md) 和 [默认资源](../../../resources/rag/README.md)。
- 提交任务已经固定知识库修订和文档版本，`BlockContext` 通过父进程代理读取、检查范围及登记证据。参见 [知识库接口](../../knowledge-api.md)。
- 现有模型准备能力支持固定文件摘要、独立依赖环境和块子进程，但不是平台设置中的 embedding 模型目录，也没有 embedding/语义搜索接口。每次块调用创建新进程，不能依赖块全局变量实现跨节点缓存。参见 [运行文件与依赖](../../platform-runtime-files.md)。
- 当前已持有的是 RapidOCR 的 PP-OCRv4 mobile 等 OCR 文件，合计约 16 MiB；未发现本轮已导入的 embedding 模型。此前讨论的 BGE-small-zh-v1.5 是候选，不是现有可用部署。
- 三类开发资源仍为包、块、契约；模型作为平台运行资产管理，不增加专用 RAG 节点、第四种业务资源或另一套流程导入协议。

首版不包含远程 embedding、多向量数据库适配、跨任务向量复用、持久化向量索引、自动文档同步、GPU 自动配置、训练微调、模型市场、多 Agent 或任务断点续跑。关键词融合和模型重排可由后续资源实现，不列为本次必交付能力。

## 本地模型与导入格式

优先评估小型中文模型 `BAAI/bge-small-zh-v1.5`，以 CPU、小批次推理为起点。其官方单份权重约 95.8 MB、输出 512 维、输入上限 512 token；这些是候选模型规格，不能当作本机运行内存或速度测量结果。

优先验证 ONNX Runtime 适配，以减少额外运行栈；现有 OCR 使用 ONNX Runtime 不代表 embedding 可以直接复用同一个依赖环境。导出格式、算子、tokenizer、池化、归一化、查询指令和依赖版本需完整核对并锁定，无法正确适配则明确调整方案，不以错误输出冒充兼容。首版至少真实验证一种完整模型制品组合。

模型导入以受支持的本地目录及声明清单为单位，不接受仅选一个权重文件就猜测模型类型。清单至少记录：

- 名称、发布者、版本或来源修订、许可证与来源说明。
- 适配器类型、权重文件、tokenizer 及所需配置文件的相对路径与 SHA-256。
- 向量维度、输入 token 上限、池化方式、归一化规则、文档/查询指令与数值精度。
- 固定运行依赖、兼容 Python/平台信息和适配器版本。

平台复制受支持文件到应用模型目录，校验后原子标记就绪；移动用户原目录不影响运行。模型身份由内容和适配配置共同确定，同名不同内容不能覆盖历史版本。只支持明确适配的结构，不执行模型目录中的任意 Python 文件或 `trust_remote_code`。首版不提供任意模型自动转换，也不通过任务隐式联网下载缺失文件。

模型文件持久保存，导入元数据和选择写入平台存储；这与文档向量仅在内存保存是两个不同生命周期。OCR 模型继续使用原有声明与准备机制，不混入 embedding 候选列表。

参考：[官方模型说明](https://huggingface.co/BAAI/bge-small-zh-v1.5)、[官方文件列表](https://huggingface.co/BAAI/bge-small-zh-v1.5/tree/main)。规格记录日期为 2026-09-22，正式接入须固定具体修订与文件摘要。

## 平台设置与模型选择

在现有平台设置页增加「本地 embedding 模型」区域：

1. 导入本地模型目录，显示检查进度、模型身份、文件大小、格式及是否就绪；失败给出具体缺项或不兼容原因。
2. 展示已经导入的模型，选择就绪模型作为后续语义检索任务的默认模型；聊天模型连接与 OCR 文件不作为可选项。
3. 支持明确触发的小样例验证，显示实际向量维度、有限数值校验和耗时，不把结构验证等同于语义质量验证。
4. 展示本地 CPU 执行说明，以及没有就绪模型时的可操作提示；不静默改用远程模型或词面检索。

首版只提供一个默认选择，避免同时增加服务级、节点级多套模型选择。提交需要语义检索的任务时解析默认选择，固定完整模型和适配器身份到任务运行快照；后续更改默认值只影响新提交任务，不影响排队或运行任务。默认模型选择属于运行设置，不单独生成服务实例版本。

在契约设计阶段增加明确的块能力声明，使编译器可以从顶层及固定子服务识别语义检索需求，并在提交阶段检查模型就绪。普通块执行代码不能任意切换本任务已固定的模型。固定模型制品不可原地更新；历史或在途引用的版本保留，首版不建设物理删除入口。

## 平台语义搜索接口

面向块的首版入口拟为异步 `context.semantic_search(request)`；以下名称与字段是设计草案，不是已经存在的 API。权威契约由平台 Pydantic 定义并推导 Schema，SDK、父进程代理、管理 API 和页面保持一致。

| 对象 | 拟包含内容 |
| --- | --- |
| `SemanticSearchRequest` | 固定知识库引用、查询文本、片段及来源列表、解析/切分身份、候选数量上限、可选最低分 |
| 片段 | 文档版本、片段 ID、正文及摘要、定位；沿用当前 Evidence 的来源结构 |
| `SemanticSearchResult` | 按相似度排序的候选、分数、模型及算法身份、范围与切分限制、实际处理统计 |
| 运行统计 | 输入 token/片段数、批次数、缓存命中、排队及推理耗时；记录实际值，不伪造供应商账单 |

块提供已解析片段，平台提供文本编码与相似度检索；接口不绑定 DOCX 格式，也不擅自重读或扩大整个知识库范围。首版接入 TaskKnowledge 路径；直接 TaskFile 检索需另补来源契约，不隐式开放任意本地文件路径。

父进程校验任务身份、知识库修订、文档版本归属、正文摘要和请求上限。摘要和归属校验不等于证明自定义解析器忠实还原原件，保留当前受信任资源边界。模型输出必须校验向量数量、维度、有限数值与有效范数，不能让错误向量进入排序。

首版采用归一化向量的余弦相似度和内存精确扫描，无需向量数据库。相同分数按片段原序稳定排序。分数不是事实可信度，也与现有词面分数不可直接相加。无最低分时 topK 只表示最接近的片段，不能据此宣称材料足以回答；显式阈值筛选后的空结果正常返回，下游仍须处理资料不足。

超长片段由默认资源按 tokenizer 边界拆分，保留准确来源定位；查询超长、无法保留定位或调用方传入不合规片段时明确报错，不静默截断。候选返回数量须与现有证据登记上限兼容。

平台内部实现 embedding 适配接口，但首版不要求向业务输出暴露完整向量。不得把向量数组写入普通节点输出、JSON 日志或历史快照。对桌面仅开放模型管理与诊断入口；首版不建设脱离任务范围的匿名全库搜索 API。

## 任务内缓存与执行生命周期

```text
提交：固定知识库修订 + 模型内容/适配器身份
  → 块读取并切分资料
  → 平台生成文档向量（同任务相同片段复用）
  → 生成查询向量 → 内存相似度排序
  → 返回候选 → 整理登记证据 → 下游生成
结束/取消/失败/应用退出：清理任务向量与临时上下文
```

向量仅保存在平台管理的任务级执行上下文。缓存身份至少包括任务、模型与 tokenizer/适配配置、文档版本、解析切分配置、片段正文摘要及文档/查询用途；不能仅用文件名、片段序号或向量维度作为键。

同一任务内跨块、循环和节点重试可复用已完整生成且身份一致的片段向量；不同任务隔离，不因正文相同而复用任务结果。失败批次不冒充完成，缓存不会改变输入顺序与搜索范围。首版不保存跨任务向量缓存，不恢复已中断任务。

本地推理在平台管理的任务级工作进程中执行，按需加载并可在本任务内复用；不阻塞 FastAPI 事件循环。父进程负责取消及异常清理，不能依赖只在正常返回时执行的清理逻辑。任务级工作进程与当前逐次创建的业务块子进程分开，通过现有受控代理模式连接，不依赖块模块全局变量。

先限制同时活跃的推理工作进程、批次及线程数，并记录真实峰值内存。达到容量限制时显式等待或报错，不无限创建模型副本。不得让等待任务持有大量模型内存；具体并发默认值依据 P2 的测量确定。首版不建设复杂常驻模型池或 GPU 调度器。

本地推理不产生供应商收费 token，也不算 Prompt 包调用 loop；单独记录本地处理 token、批次和耗时，通过任务取消、执行超时、文本/批次/内存上限约束。沿用现有 LLM loop/token 定义，不把本地统计混入远端实际用量。限额失败不得通过缩小资料范围伪装成功。

拟增加模型未选择、模型未就绪、不兼容、输入超限、推理失败及容量超限等明确错误；命名在契约阶段统一。依赖、模型和取消错误不走业务输出契约重试；输出契约失败仍沿用现有生产节点重试规则。

## 持久化、历史与现有资源兼容

| 持久保留 | 任务结束清理 |
| --- | --- |
| 导入模型文件、模型清单与固定依赖 | 文档和查询向量 |
| 默认模型选择与任务固定模型身份 | 任务内临时向量索引及检索缓存 |
| 原件、文档版本、知识库修订 | 推理工作进程和临时工作文件 |
| 查询、算法参数、实际候选/选用证据、范围限制与耗时统计 | 任务内模型加载状态 |

应用重启后保留模型选择与历史证据，未结束任务继续遵守 `APPLICATION_INTERRUPTED`，不续跑。历史记录能解释当时使用的模型和证据；不声称未保存向量即可逐位重现历史排名。

默认新增 `resources/rag/blocks/semantic_search.py`，尽量保持 `ParsedCorpus → SearchResults`，继续复用整理证据与下游业务包。需补充的算法/模型记录字段应统一改动权威契约及调用方，不能复制多份不一致结构。

现有词面与完整短语检索资源继续可用，旧任务和服务固定引用不变。新增 SDK 方法、块能力声明和模型运行快照须核对源码摘要、依赖锁及历史恢复；是否需要编译协议升级在 P1 明确，不能默认用新解释器重写旧快照。
