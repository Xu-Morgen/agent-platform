# 单后端并发消费者池交付记录

日期：2026-09-21。状态：实现及轻量验证完成，当前配置说明见 [项目入口](../../../readme.md#任务并发配置)。

## 用户需求

将单后端内的单任务消费者改为可配置的并发消费者池，使同一个服务接口提交的多个任务能够同时执行。本次不改为多后端进程，不增加任务内部并行分支。

## 实施结果

1. `RunWorker` 管理固定数量的异步消费者，共享现有 FIFO 队列；消费者等待任务与清理完成后再领取下一条。
2. 默认并发 4，配置范围 1～64，设为 1 恢复串行。后续同日按用户要求改为「平台设置」页面落库、重启后应用，替代本阶段最初的启动参数方案，最终验证见 [平台设置交付](platform-settings.md)。
3. 同一服务的每次提交仍创建独立任务，保留固定实例/环境快照；运行上下文、模型/API 传输、预算、步骤与结果按任务隔离。无需修改业务契约、实例版本或数据库格式。
4. 健康检查检查全部消费者；任一消费者停止或后端关闭时拒绝新任务，提交的输入异步校验前后均检查。重复启动执行器被拒绝，不静默丢失原消费者。
5. 退出先停止受理，同时取消全部消费者并等待传输和上下文清理，再清空排队任务、写入终态和释放环境占用；重复退出调用通过同一锁串行收敛。传输关闭异常时仍释放当前任务上下文和环境占用。
6. 同步更新项目使用说明、架构、持久化边界、R4 细化状态和路线图。

## 已执行验证

使用已有 Python/Node 依赖、内存仓储和合成输入，未安装依赖、未调用线上模型或接触实际业务数据库。

- 通过实际 FastAPI 提交接口加载已有最小 Prompt 包并创建临时服务，使用本地 HTTP 模拟模型端点阻塞/释放请求；并发配置分别为 1、2、4，观测同时到达的请求峰值恰好等于配置值，其余任务排队。
- 同一服务多次调用的输入/结果对应正确，各任务仅记录自己的步骤、一次模型调用及 11 token 的模拟供应商用量。
- 环境在排队/运行任务占用期间拒绝更新，任务完成后全部释放。
- 主动取消运行任务保持等待传输语义；其他任务继续运行。排队取消不发送模型请求，不妨碍后续任务领取。
- 一个任务输出契约失败不会终止消费者，也不影响另一个任务成功。
- 两个消费者运行、三个任务排队时，同时发起两次退出：全部任务正确终止，两个本地请求断开，队列计数归零，环境占用清空，退出后拒绝提交。
- 单个空闲消费者异常取消后健康检查返回 503，并拒绝新任务；另一消费者保持运行，随后正常退出清理。
- 初始启动参数方案的默认值、环境变量、显式参数优先级、应用工厂传递及非法值检查通过；该配置入口已被后续平台设置替代。
- 使用实际桌面 `Backend` 启动显式内存后端，验证环境变量传递链路、启动握手、健康检查与控制管道正常退出。
- Python 源码语法检查和 Git 差异检查通过。

临时验证脚本与缓存已清理，不保留业务实例自动组装脚本或回归套件。

## 验证边界与未实现项

本地 HTTP 模拟端点用于证明并发和生命周期行为，不代表真实模型质量或线上限流验收。本阶段未进行 PostgreSQL 并发压力测试或吞吐基准；数据库仍是单后端同步存储。未增加排队容量、背压、按连接限流、运行时热修改并发数、多进程/多机任务认领、租约或任务恢复。消费者异常停止时报告不健康并拒绝新任务，需检查并重启后端，不自动重放任务。
